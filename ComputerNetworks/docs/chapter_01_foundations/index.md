# 网络基础 { #1 }

打开浏览器、敲下网址、按下回车——在用户眼里，这只是一句简单到不能再简单的请求：「请把首页发给我」。可这句请求一旦离开你的电脑，就立刻面对三个躲不开的现实难题：

1. **找谁？** 世界上有数十亿台联网设备，这句话究竟要送往哪一台机器？
2. **交谁？** 送到了那台机器，上面可能同时跑着网页服务、数据库、后台监控，怎么确保它不敲错门？
3. **怎么送才快又稳？** 网线和无线电波是大家共用的，发消息的人此起彼伏，数据怎么切块上路？半路堵车、信号迟到甚至丢了，又为什么会发生？

如果把这三件事全都硬塞进浏览器里去操心，那每换一种无线网卡、每升级一次光纤设备，全世界的软件都得推倒重写。早期的计算机通信确实常常为单一业务量身定制，可随着主机种类、操作系统和物理链路爆炸式增长，任何一方都不可能通晓所有底层细节。

互联网能从几台实验室主机演进成覆盖全球的基础设施，很大程度上归功于两个奠基性的工程抉择：**分层**（layering）与 **分组交换**（packet switching）。分层把庞杂的通信任务切成边界清晰的模块，让每一层只管自己的一亩三分地；分组交换则把大块数据拆成标准小包，让成千上万份突发流量得以共享同一组昂贵的线路。

## 本章路线：用同一份请求走通全章

为了不把概念讲空，本章只紧紧盯住一份真实的小请求，从两个视角把它彻底看透：

1. 先看 **结构与分工**——[分层、封装与协议](01_layering_and_encapsulation.md)：跟着一句最简单的 `GET /` 请求，看网络怎样给它逐层套上不同用途的地址和外包装，沿途的中转设备每走一跳又拆掉了哪一层、换上了哪一层。
2. 再看 **时间与性能**——[分组交换与网络性能](02_packet_switching_and_performance.md)：拿同一个 1200 字节的分组算一笔明白账，把数据从发出到抵达的耗时拆成四段，搞清楚为什么把宽带速率翻一倍甚至十倍，网页响应却未必跟着快十倍。

把这两篇连起来，你就得到了一条贯穿整个网络的底层因果链：

```text
应用写下请求报文
  -> 各层依次套上自己的控制信息（封装）
  -> 数据切成分组，与他人的流量共享链路
  -> 沿途设备先收齐再查表转出，逐跳接力
  -> 到达终点后逐层拆封，交给目标程序
```

## 学完本章你能回答什么

读完本章的两篇内容后，你可以用下面五个问题检验自己是否真正过关：

1. 面对一次普通的网页访问，你能用五层模型说清楚每一层分别干了什么活吗？
2. 「协议」「服务」「接口」这三个容易混在一起的词，到底各自指代什么？
3. 已知链路速率和分组大小，你能随手算出把这个分组推上线缆需要多长时间吗？
4. 为什么有时候家里的千兆宽带测速跑得飞快，打开网页或打视频电话却依然觉得卡顿？
5. 为什么说网络里发生了「丢包」，绝大多数时候并不是网线断了或者光纤老化？

## 本章和后面十章的关系

第 1 章搭起的是整座大厦的骨架。后面的章节不过是拿着放大镜，逐层走进去看清每个齿轮怎样转动：

- **第 2 章**聚焦应用层，看程序之间怎样约好「消息是什么意思」，以及网址怎样一步步落到正在监听的程序；
- **第 3–4 章**深入传输层，看两端如何在随时可能丢包、乱序的路上，既保证字节滴水不漏，又懂得在拥堵时主动踩刹车；
- **第 5 章**走向网络层，看 IP 地址怎样划分版图，路由器又靠什么在茫茫互联网中算出下一跳；
- **第 6 章**落脚链路层，看局域网里最后那一根网线或一片无线空域上，数据帧怎样精准交付；
- **第 7–10 章**则把视野扩展到安全信任边界、容器虚拟网络、代理与负载均衡，以及大型数据中心内部的高速互联，最终在 **第 11 章**用真实案例和排障工具把整条链路完全打通。

安全机制并不会像罩子一样单独套在最外头，它可能嵌入应用、传输、网络甚至链路等多个层次。以后每遇到一个新协议，你都可以随时回到这一章，问自己三个老问题：它站在哪一层？给数据多加了哪几个字节的头尾？又为此付出了什么样的性能代价？

!!! question "出发前先猜一猜"
    如果你把家里的宽带速率从 100 Mb/s 升级到 1 Gb/s（整整快了 10 倍），但从你家到目标网站机房的物理距离和沿途延迟没有变，打开一个很小的网页，耗时能缩短到原来的十分之一吗？

    先卖个关子：答案通常是否定的。小网页本身只有几千到几十万字节，把它推上高速线路花的时间本来就短得几乎察觉不到；真正拖慢体验的，往往是信号来回跑一趟的物理传播时间、查网址和建立连接来回确认的回合数、服务器的处理速度，以及半路路由器里的排队等待。读完下一节和第二节，你就能亲手把这笔账算得清清楚楚。
