# 从服务名到监听中的进程

**先修**：[HTTP](01_http_https.md)、[DNS](02_dns.md)。

**读完能做**：用一个本机服务解释名称、IP、端口和监听 socket 的关系。

## 先让两个进程说话

在一个空目录里启动服务，只暴露在本机回环地址：

```sh
python -m http.server 8000 --bind 127.0.0.1
```

另开终端访问 `http://127.0.0.1:8000/`，或者运行：

```sh
curl -i http://127.0.0.1:8000/
```

这里 IP 指向本机回环接口，端口用于把连接交给监听的 socket。HTTP 客户端先建立 TCP 连接，再发送 HTTP 请求。服务端通过监听 socket 接受连接，每个已建立的 TCP 连接有自己的本地与远端地址和端口。服务器可同时处理来自不同客户端端口的连接。

## 三个只改一项的对照

| 改动 | 先预测 | 再观察 |
| --- | --- | --- |
| 把 URL 换成端口 8001，确认没有其他程序监听 | 找不到对应监听者 | 连接失败，HTTP 请求尚未到应用 |
| 服务保持绑定 127.0.0.1，从本机试它的局域网地址 | 服务只接受发往回环地址的连接 | 即使同一台机器也可能访问不到这个地址 |
| 服务正常，访问一个目录中不存在的文件 | TCP 建连成功并发送 HTTP | 服务返回 HTTP 404 |

主机名由系统解析出一个或多个地址，直接用 IP 时跳过名称解析。某些系统会同时为 `localhost` 提供 IPv4 和 IPv6 地址；而示例明确只监听 IPv4 回环。观察差异时，记下客户端实际尝试的地址。IPv4 通配地址 `0.0.0.0` 用于监听本机各 IPv4 接口，客户端仍需连接一个实际可达地址，是否能连接还取决于路由和防火墙。

## 自测

从另一台电脑访问服务得到 HTTP 404，说明成功走到了哪层？如果只收到连接超时，又能得出什么结论？

??? note "参考思路"
    404 说明某个 HTTP 响应方收到了请求，接着检查路径、代理和后端身份。超时只表示在给定时间内没有完成操作，要再区分 DNS、TCP 建连、TLS 或应用响应阶段。
