# IPv4、子网与地址规划

当你的电脑拿到一个目标 IP 地址准备发包时，它做的第一件事既不是立刻把数据推上网线，也不是盲目全部扔给路由器，而是先飞快地做一道二选一判断：

- **情况 A**：目标机器就在我所在的这一小片本地网络里——那我根本不用麻烦路由器转手，直接在这段局域网上找到对方的网卡 MAC 地址发过去就行！
- **情况 B**：目标机器在另一片网络里——那我喊破喉咙它也听不见，必须把数据先交给负责「转出本网」的大门卫（默认网关），请它帮我接力送往外面的世界。

电脑凭什么一眼分出「自己人」还是「外网人」？秘密就藏在 **IPv4** 地址末尾常常跟着的那道斜杠数字里——比如 `192.0.2.34/26`。这串 32 比特的地址被划成了前后两截，前 26 位像「省市街道邮编」，标明了这台机器属于哪一片 **子网**（subnet）；后 6 位像「门牌号」，区分同一片子网里的不同主机。这笔算术每台联网设备每天都在默默算上百万次，今天我们亲手算一次，把它彻底算明白。

## 自己算一次：目标是否和我在同一个子网？

假设你的主机地址是 `192.0.2.34/26`。IPv4 地址总共 32 比特（按每 8 比特一组写成四个 0–255 的十进制数，称为点分十进制）。斜杠后面的 `/26` 意味着：
- **前 26 比特**固定锁死，用来标识你所在的网络前缀；
- **剩下的 $32 - 26 = 6$ 比特**留给这片子网内部自由分配。

6 个二进制位一共能组合出 $2^6 = 64$ 个不同的数字。也就是说，`/26` 把最后一段 `0`–`255` 整整齐齐切成了四块，每块正好 64 个地址：`0`–`63`、`64`–`127`、`128`–`191`、`192`–`255`。

你的主机 `.34` 落在第一块 `0`–`63` 之中。现在同时来了两个目标：
- 目标 1 是 `192.0.2.60`：它同样落在 `0`–`63` 里，前 26 位和你一模一样！主机立刻判定「咱俩是同子网邻居」，直接走本地链路寻找对方的网卡地址交付；
- 目标 2 是 `192.0.2.70`：虽然前三段长得一模一样都是 `192.0.2`，可 `70` 已经跨进了第二块 `64`–`127`，前 26 位和你不同！主机毫不犹豫地把它打包发往默认网关。（当然，这里先假定地址和路由配置本身没有配错。）

你看，**绝对不能光凭肉眼看前三段十进制数相不相同就猜是不是同一个网段**，真正说了算的，是二进制前 $N$ 位网络前缀！

??? question "既然 `192.0.2.63` 落在 `0`–`63` 这第一块里，我可以把它分配给办公室里一台普通电脑当 IP 吗？"

    不行！在传统 IPv4 `/26` 子网约定里，整块地址的**最开头**和**最末尾**各有一个保留用途：`.0`（主机位全 `0`）作为这片子网本身的**网络地址**；`.63`（主机位全 `1`）作为这片子网的**定向广播地址**（发往这个地址的包会送给子网里所有主机）。因此真正能配给普通电脑或网关接口的可用范围是 `.1` 到 `.62`。

既然我们已经摸到了 `/26` 的门道，再往深处问一句：互联网为什么非要费劲引入「前缀长度」这一套写法，而不是给全球每台电脑发个毫无规律的身份证号呢？

## 地址为什么必须带前缀：CIDR 与路由聚合的诞生

IPv4 地址只有 32 比特，总共约 42.9 亿个地址。假如全世界的 IP 像随机抽签一样散落各地，毫无层级规律可言，那么互联网核心的每一台路由器就必须死死记住**几十亿条「具体到每一台主机该往哪个口送」的精确路由**——不仅硬件内存当场爆炸，每次有新设备插拔，全球路由表都要跟着震荡。

早期互联网曾尝试死板地把地址切成 A、B、C 三大类（前缀固定死为 `/8`、`/16`、`/24`），结果要么浪费惊人（一家只有 500 台电脑的公司嫌 `/24` 装不下，只好要走一个含 65536 个地址的 `/16`！），要么地址表膨胀太快。

为了救火，互联网在 1990 年代引入了沿用至今的 **无类别域间路由**（CIDR，Classless Inter-Domain Routing）。CIDR 彻底废除了僵硬的 A/B/C 分类，允许前缀长度在 `0` 到 `32` 之间灵活划分，写作 `a.b.c.d/x`（比如 `192.0.2.0/24` 表示前 24 位是网络前缀，后 8 位是子网内部地址）。

CIDR 带来了一个价值千金的能力——**层次化聚合**：一家大型企业或运营商只需要向全球互联网宣告一条粗粒度的总前缀（比如一个 `/16`），然后自己在内网里把这块领地精细切分成几十个 `/24`、`/26` 分别配给不同楼层和部门。外面的骨干路由器根本不需要知道你们公司三楼财务部是哪段子网，只要记住「凡是匹配这个 `/16` 的，统统往这家运营商的方向送」就够了！

## 最小完整例子：彻底解剖一个 `/26` 子网

为了把二进制、掩码和可用范围彻底钉死，我们再手把手解剖隔壁那块 `192.0.2.64/26`。

前 26 比特为网络前缀，剩余主机位 $32 - 26 = 6$ 比特，整块子网的地址总数为：

$$
2^{32-26}=64.
$$

起始于 `64`，连续数 64 个数，终点是 $64 + 64 - 1 = 127$，即范围从 `192.0.2.64` 到 `192.0.2.127`。在传统 IPv4 语义中，它的四项关键参数一目了然：

- **网络地址**（主机位全 `0`）：`192.0.2.64`
- **可分配主机地址**：`192.0.2.65` 到 `192.0.2.126`（共 $64 - 2 = 62$ 个，通常其中 1 个会配给这片子网的默认网关接口）
- **定向广播地址**（主机位全 `1`）：`192.0.2.127`
- **子网掩码**（subnet mask，前 26 位全 `1`、后 6 位全 `0`）：`255.255.255.192`（因为最后一个字节 `11000000` 换算成十进制正是 $128 + 64 = 192$）

> **小提醒**：千万别把「可用地址数 = $2^h - 2$」背成僵化的教条！在路由器之间点到点直连链路使用的 `/31` 子网，或某些特殊单主机路由 `/32` 场景里，标准允许例外约定，并不需要机械减 2。

### 机器内部怎样一瞬间判断是否同网段？

硬件和操作系统不用十进制加减，而是用最快的二进制 **按位与**（bitwise AND）运算：把**本机 IP** 和 **目标 IP** 分别与**子网掩码**做按位与，留下来的就是各自的网络前缀——结果一模一样就是同子网，哪怕差了 1 个比特就交给默认网关！

拿刚才的 `192.0.2.64/26` 检验一下：`192.0.2.70` 和 `192.0.2.100` 与 `255.255.255.192` 按位与之后都等于 `192.0.2.64`，两者稳稳同网段；而 `192.0.2.130` 按位与后得到 `192.0.2.128`，前缀不同，立刻走默认网关。

知道地址怎么算之后，一个很现实的问题冒了出来：你买了一台新笔记本，走进咖啡馆连上 Wi-Fi，可你从来没手动输入过什么 `192.168.x.x/24`、子网掩码和默认网关啊——你的电脑到底是怎么在几秒钟内「无师自通」领到这一套配置的？

## 地址从哪里来：静态配置与 DHCP 自动发号

一台主机想要正常访问互联网，至少得凑齐四样基本配置：**本机 IP 地址**、**子网前缀长度（掩码）**、**默认网关 IP**，以及至少一个 **DNS 解析器 IP**。

机房里的核心服务器、路由器接口通常由管理员手工固定写入（**静态配置**），以防地址变动导致别的服务找不到它们；可要让咖啡馆顾客、宿舍楼学生、公司几千台笔记本也一个个手工填表，不仅烦琐得要命，只要两个人填重了同一个 IP 就会当场撞车断网。

于是，局域网里普遍请出了一位贴心的自动发号员——**动态主机配置协议**（DHCP，Dynamic Host Configuration Protocol）。当你刚连上 Wi-Fi、连自己叫什么都不知道时，电脑会和局域网里的 DHCP 服务器（在家就是你的无线路由器）飞快完成一轮经典的「四步对话」（常简记为 **DORA**）：

1. **Discover（广播找人）**：新主机在本地局域网大喊一声：「请问这里有 DHCP 服务器吗？我需要一个地址！」
2. **Offer（给出方案）**：DHCP 服务器从空闲地址池里挑一个还没人用的 IP，附带掩码、默认网关、DNS 和**租约有效期**（lease time）报给新主机。
3. **Request（正式申领）**：新主机回复：「好，我正式申请使用你刚才给的那个 IP！」（如果网里有两台 DHCP 服务器同时报价，这一步也能明确告诉大家最终选了谁。）
4. **ACK（盖章生效）**：DHCP 服务器确认签发，记入租约账本；主机立刻把这四件套配到网卡上，开始冲浪！

采用**租约机制**极其聪明：顾客喝完咖啡合上电脑离开咖啡馆，租约到期后 IP 自动回收到地址池里循环利用，彻底避免了地址被「只借不还」的过客占光。

不过，自动化也带来了隐蔽的安全风险：DHCP 刚起步时靠广播找人，并不校验谁才是真正的官方服务器。如果有人在公司或公共局域网里悄悄插上一台伪造的流氓 DHCP 服务器抢先应答，把恶意机器配成你的「默认网关」或「假 DNS」，你的所有流量就会神不知鬼不觉地先绕经攻击者！因此企业网络常在交换机上开启端口保护机制（如 DHCP snooping，只放行合法端口发出的 DHCP 报价）来堵住这一漏洞。

排障时也要谨记：**DHCP 成功拿到 IP，绝不等于互联网一定能通！** 它只证明你和本地发号员聊上了；要是发下来的默认网关填错了、上游宽带欠费断了、NAT 出错了，或者被防火墙拦住了，你依然打不开网页。排查时必须按「本地配置 → 网关连通 → 路由外网 → 应用服务」逐段剥洋葱。

## 公有、私有与特殊保留地址

翻看你在家里、公司或校园网里领到的 IP，十有八九会撞见这三张熟悉的面孔：

- `10.0.0.0/8`（约 1677 万个地址，大型企业、云厂商和容器网最爱用）
- `172.16.0.0/12`（`172.16.0.0` 到 `172.31.255.255`，约 104 万个地址）
- `192.168.0.0/16`（约 6.5 万个地址，几乎每台家用路由器默认的 `192.168.1.x` 都在这里）

这三段叫作 **私有地址**（private address）。它们不是为某一家独占的，而是免费开放给全世界任意家庭、公司和云端内网**重复复用**的——你家客厅笔记本是 `192.168.1.10`，地球另一端几百万户人家的笔记本也可以同时叫 `192.168.1.10`，彼此毫不冲突！代价是：**公共互联网的路由器一律拒绝转发私有地址**。这些内网设备想出门访问公网网站，通常得在边界网关处做一次「把私有地址临时改写成公网地址」的翻译——这就是[下一节](02_ipv6_nat_icmp.md)的主角 NAT。

除此之外，还有几段肩负特殊使命的保留地址务必眼熟：
- `127.0.0.0/8`：**回环地址**（最常见的 `127.0.0.1`），数据永远只在自己电脑的协议栈里打转，不出网卡；
- `169.254.0.0/16`：**链路本地地址**，当你把电脑插上网线却一直找不到 DHCP 服务器时，操作系统可能会自动给自己挑一个 `169.254.x.x` 的应急地址——排障时一旦在网卡上看到这个网段，十有八九说明 DHCP 没通；
- **文档示例保留段**（如本教程用到的 `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`）：标准组织专门划出来写教材和文档用的虚拟地址，确保读者照抄命令时不会误打到真实世界里某台无辜服务器。

## 子网规划的权衡与 VLSM

假如你是一家创业公司的网络管理员，手里分到一个 `10.10.0.0/22`（共 1024 个地址）的地址块，要分给三个部门：研发部有 100 台机器，行政部只有 12 台机器，机房两台核心路由器之间点到点互联只需要 2 个地址。

如果图省事，全部一刀切按定长分成 `/24`（每块 256 个地址），那路由器互联白白浪费了 250 多个地址，整个地址块很快捉襟见肘。**可变长子网掩码**（VLSM，Variable Length Subnet Mask）正是为了按需裁剪而生：给研发部切一个 `/25`（可用 126 个），给行政部切一个 `/28`（可用 14 个），给点到点链路切一个 `/30` 或 `/31`，把地址榨出最大价值！

不过，真实的工程规划远不只是做算术拼图：你还得替未来两三年的团队扩张留出增长余量，把冗余网关、随时暴涨的容器和虚拟机算进去，还要兼顾路由聚合和安全隔离。把几千台设备硬塞进同一片巨大局域网看似省了路由配置，可一旦有台机器中了广播风暴病毒，整栋楼的网都会跟着瘫痪；反过来，子网切得过分零碎，路由表和防火墙规则又会膨胀到没人敢动。好规划永远是在「易管理」与「好隔离」之间取中庸。

## 路由聚合：把零散门牌揉成一条总路牌

CIDR 的反方向魔法，是把多段**连续且二进制边界对齐**的小前缀，向上合并成一条更短的大前缀，称为 **路由聚合**（route aggregation / supernetting）。

例如，一家分支机构内部用着 `192.0.2.0/25`（`.0`–`.127`）和 `192.0.2.128/25`（`.128`–`.255`）两片相邻子网。它们的前 24 位完全相同，第 25 位恰好一个是 `0`、一个是 `1`，正好无缝拼成一整块 `192.0.2.0/24`！对外宣告时，只需向核心网络发这一条 `/24` 汇总路由即可，核心路由器的表项立刻减半。

但聚合绝不能贪大求全：假如你实际上只拥有 `.0/25`，隔壁 `.128/25` 归另一家公司所有，你却图省事对外宣告了整块 `.0/24`，那么别人发给那家公司的流量就可能被你的汇总路由错误吸进你家大门，最终变成丢包黑洞！

!!! question "随堂自测"
    一台主机的配置是 `10.1.5.130/25`。请心算：它所在子网的网络地址和广播地址分别是什么？

    `/25` 意味着剩余主机位为 $32 - 25 = 7$ 比特，每一段子网正好包含 $2^7 = 128$ 个地址——即把最后一段切成了 `0`–`127` 和 `128`–`255` 两半。主机的 `.130` 落在后一半 `128`–`255` 中，因此网络地址是 `10.1.5.128`，广播地址是 `10.1.5.255`（可用主机范围 `.129` 到 `.254`）。
