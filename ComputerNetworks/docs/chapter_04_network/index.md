# 网络层 { #4 }

想象你寄出一封从广州发往哈尔滨的挂号信。在邮局把信收进去的那一刻，并没有哪位神秘调度员替这封信提前画好「先上哪辆货车、几点转哪趟火车、经过哪几个县城」的全程路线图。真实运作方式要聪明得多：沿途每一个分拣中心只需要扫一眼信封上的收件地址，查一下自己手头那张指路表，做出一个极其纯粹的局部决定——「发往黑龙江方向的，统统装进北上的车厢！」下一站的分拣中心如法炮制，一棒接一棒，信件自然就抵达了千里之外的收件人手里。

在互联网里，承担这份「全球跨网寻路与逐跳接力」重任的，就是 **网络层**（network layer）。

前面第 3 章和第 4 章里，传输层在通信两端的端系统上施展魔法，保证了可靠字节流、流量控制与拥塞控制；可数据包一旦离开本机网卡，面对成千上万张由不同运营商、企业、校园拼起来的异构网络，它全指望网络层回答三个根本问题：

1. **地址怎么编？** 世界上有数十亿联网设备，怎样设计 IP 地址结构，才能让路由器不必死记每一台电脑的门牌，一眼就能判断「就在身边」还是「远在天边」？
2. **地址不够用、半路送不到怎么办？** IPv4 地址早就捉襟见肘，家庭和公司内网怎样借道公网出门？新一代 IPv6 又做了哪些革新？数据包半路迷路或太大过不去时，谁来给源主机通风报信？
3. **下一跳怎么选、路线谁来算？** 当路由器同时收到几条都能匹配上的指路规则时听哪一条？而路由器里那张密密麻麻的转发表，又是靠什么算法在瞬息万变的全球网络里算出来的？

## 核心服务模型：为什么 IP 刻意只承诺「尽力而为」？

初学网络层时，很多人会对 **IP**（Internet Protocol）的服务承诺感到意外——它显得太「佛系」了！IP 提供的是一种叫作 **尽力而为**（best-effort）的服务模型：它不保证分组一定能送到，不保证后发的不会先到，不保证不重复，也不承诺固定的低延迟或最低带宽。

可正是这份看似「什么都不担保」的克制，造就了互联网跨越半个世纪的勃勃生机。因为核心路由器不需要理解你的业务需不需要重传、也不必为几亿条连接维护复杂状态，任何新发明的物理链路（从早年电话拨号到今天的星链卫星和 400G 光纤）只要能塞进一个 IP 数据报，就能无缝接入全球互联网；而需要可靠有序的应用交给 TCP/QUIC，需要低延迟的实时语音自己兜底，各取所需。

当然，代价也同样透明：**底层发生的一切失败，必须由端系统自己看见并消化。** 一个 IP 分组可能因为路由器队列溢出、查不到路由、跳数耗尽、体积超过链路 MTU，或者被防火墙规则拦截而在半路悄然消失。虽然 ICMP 会在部分场景下好心寄回报错消息，但发包方绝不能天真地以为「只要丢了包，就一定有人告诉我为什么」。

## 学完本章你能做到什么

1. 给定任意一个带前缀的 IPv4 地址（如 `/26` 或 `/25`），能随手算出它的网络地址、广播地址、可用主机范围，并判断两台机器是否在同一个子网；
2. 讲清楚私有地址、默认网关、DHCP 和 NAT 在日常上网时是如何环环相扣协作的；
3. 熟练读写 IPv6 压缩格式，理解 `ping` 和 `traceroute` 背后如何巧用 ICMP 与跳数限制；
4. 面对多条重叠的路由表项，用**最长前缀匹配**准确选出出接口；
5. 清楚区分「路由器逐包高速查表转发」与「路由协议在后台算路建表」两件完全不同时间尺度的工作。

!!! tip "带上一条最稳固的直觉出发"
    普通路由器从来不为你的数据包操心「从起点到终点的整条完整路径」。它收到包后只做一件事：看一眼目的 IP 前缀，查表挑出**下一跳**交给邻居；下一台路由器再重复同样的动作。数据跨越半个地球走出的宏观路径，是由沿途十几台路由器各自独立的局部决定无缝接力拼出来的。
