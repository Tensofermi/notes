# 以太网、Wi-Fi 与 ARP

现在，你的电脑终于准备把一个写好目的 IP 的数据包推上眼前这段局域网了。可链路层协议（以太网或 Wi-Fi）根本不认什么 IP 地址，它只认局域网里每一块网卡自带的 48 位硬件门牌——**MAC 地址**。

麻烦立刻来了：电脑手里只握着下一跳设备的 IPv4 地址，却压根不知道对方网卡的 MAC 地址是多少！怎么办？最朴素、也最管用的办法就是在局域网里扯着嗓子广播喊一嗓子：「各位邻居听好！谁拥有这个 IPv4 地址？请把你的 MAC 地址报给我！」

负责完成这场局域网「现场喊话认人」的，就是 **地址解析协议**（ARP，Address Resolution Protocol）。别小看这短短一问一答，它背后藏着初学者做网络题和排障时最容易答错的一道陷阱题。

## 访问远处的服务器，电脑先问谁的 MAC 地址？

假设你正在家里用笔记本访问远在异地机房的一台网站服务器。电脑查完自己的子网掩码和路由表，发现目标服务器压根不在家里这片局域网里，路由表告诉它：「走默认路由，下一跳交给家里路由器（默认网关）！」

此时，你的笔记本准备封装这第一跳的以太网帧。请问：**它发出的 ARP 广播，问的是远方网站服务器的 MAC 地址，还是家里默认网关的 MAC 地址？**

顺着前几章铺下的直觉，答案毫无疑问是 **家里默认网关的 MAC 地址**！原因很简单：你的笔记本只管把帧稳稳送到「眼前这一跳的相邻设备」，远方服务器根本不在这片局域网里，喊破喉咙也听不见你的广播。于是，笔记本发出的这第一跳数据包呈现出极其精妙的「内外双目标」结构：
- **外层以太网帧的目的 MAC**：填的是家里默认网关的网卡地址（管眼前这一跳）；
- **内层 IP 数据报的目的 IP**：原封不动填着远方网站服务器的地址（管最终目的地）。

等家里路由器收下这帧，剥掉以太网外壳，看一眼里面的目的 IP，查路由表选出运营商那头的下一跳，再换上一套全新的链路层外包装继续接力——这就是为什么同一个数据包在出发那一刻，外层 MAC 和内层目的 IP 完全可以指向两台不同的机器！

??? question "如果我只是在同一个办公室局域网里把文件发给隔壁同事，数据经过办公室里的普通二层交换机时，交换机看的是 IP 地址还是 MAC 地址？"

    普通二层交换机只看外层帧头的 **目的 MAC 地址**！它压根不去拆里面的 IP 首部，也不懂什么是子网和路由。只有当数据包需要跨出当前子网、送到另一个网段时，才轮到具备 IP 路由能力的三层设备（如默认网关路由器）拆包看目的 IP 并重新选路。

理顺了「问谁」的直觉，让我们把镜头拉近，先看清以太网帧和交换机这两块有线局域网的基石。

## 以太网帧里到底装着什么？

剥开一根网线里飞奔的典型 **以太网帧**（Ethernet frame），你会看到五个排得整整齐齐的部件：

```text
+------------+------------+--------+---------------------+----------+
| 目的 MAC   | 源 MAC     |  类型  |   载荷（如 IP 包）   | 校验 FCS |
|  (6 字节)  |  (6 字节)  | (2字节)|    (46–1500 字节)    | (4 字节) |
+------------+------------+--------+---------------------+----------+
```

- **目的 MAC 与源 MAC**（各 6 字节，共 48 比特，常写成如 `aa:bb:cc:dd:ee:ff` 的十六进制）：标明这一跳「谁发的、交给谁」。按接收范围分为三类：**单播地址**（精准给某一块网卡）、**多播地址**（给订阅了同一组播的一群网卡）、以及全 `1` 的 **广播地址** `ff:ff:ff:ff:ff:ff`（大喊一声，同一广播域里所有网卡都要收下看一眼）。
- **类型（EtherType）**（2 字节）：这就是第 1 章讲「解复用」时提到的向上交付路标——告诉接收方操作系统「载荷里装的是 IPv4（`0x0800`）、IPv6（`0x86DD`）还是 ARP（`0x0806`）」。
- **载荷**（常见最大 1500 字节，即标准以太网 MTU；某些高速数据中心内网会启用高达 9000 字节的巨型帧，而多层隧道封装则会挤占可用载荷）。
- **帧校验序列 FCS**（4 字节）：正是上一节讲过的 CRC-32，用来在当前这一跳把受损坏帧当场筛出去。

再次体会 MAC 地址与 IP 地址的本质区别：**MAC 地址像人的身份证号，是扁平的、跟着硬件网卡走**——哪怕你拎着笔记本从北京飞到纽约，网卡的 MAC 地址纹丝不动，所以核心互联网路由器绝不可能拿扁平的 MAC 地址去做全球分层路由；而 **IP 地址像你当下租住的邮编和门牌**，走到哪片子网就换哪片前缀，专供跨网寻路。

既然 MAC 地址毫无地理规律可言，把二十台电脑用网线插进一台刚买回来、连说明书都没拆的 **二层交换机**（switch）上，交换机怎么知道哪台电脑插在 1 号口、哪台插在 8 号口呢？

## 交换机如何学习 { #switch-learning }

二层交换机最让人拍案叫绝的本领，叫作 **即插即用与自学习**（self-learning）——管理员一行配置都不用敲，插上电就能自动把每个网口后面连着谁摸得门儿清！

它的秘诀是内部维护一张「**MAC 地址 ↔ 交换机物理端口号**」的转发表。每当一个以太网帧从某个端口（比如 1 号口）冲进来，交换机利落地干两件事——先「记笔记」，再「做转发」：

1. **看「源 MAC」偷偷记笔记**：既然这个帧的源 MAC 是 `A`、且它是从 1 号口钻进来的，交换机立刻恍然大悟：「哦！机器 `A` 原来就在 1 号口方向！」马上把 `A -> 1 号口` 写进表里，并附上一个倒计时（**老化时间**，通常几分钟——万一待会儿有人把 `A` 拔下来插到 5 号口，旧条目过期删掉才不会永远发错）。
2. **看「目的 MAC」决定怎么发**：
   - **目的已知（查到了）**：比如表里早已记着 `B -> 4 号口`，交换机精准地只把帧从 4 号口送出去（如果发现目的和源都在同一个口，干脆过滤丢弃），绝不打扰其他 18 个端口的电脑！
   - **目的未知（表里还没见过 `B`）**：交换机没办法，只好把帧复制多份，向**除入端口（1 号口）以外的所有其他端口**统统发一份——这叫 **泛洪**（flooding）。一旦真正叫 `B` 的电脑收到并回了一个帧给 `A`，交换机瞬间又从回包的源 MAC 学会了 `B -> 4 号口`，下一次就变成精准单播了！
   - **广播帧**：凡是目的 MAC 写着 `ff:ff:ff:ff:ff:ff`（比如 ARP 请求或 DHCP 发现），交换机无条件向同一广播域的所有其他端口泛洪。

这套自学习机制极其省心，可它偏偏藏着一个致命死穴——**千万不能在普通二层交换机之间拉网线接成一个物理环路！**

试想把三台交换机首尾相连围成一个三角形，此时只要有一台电脑发出一个 ARP 广播帧：交换机 1 把它泛洪给 2 和 3，2 又泛洪给 3，3 又泛洪回 1……还记得吗，**以太网帧头里可没有 IP 首部那样的 TTL 跳数限制！** 这个广播帧会在环路里以光速无限兜圈子并呈指数级复制，不到一秒就把整栋楼的交换机 CPU 和带宽活活烧死——这就是运维闻风丧胆的 **广播风暴**（broadcast storm）！

为了既保留冗余网线防断线、又绝不闹广播风暴，传统二层网络引入了 **生成树协议**（STP，Spanning Tree Protocol），自动在逻辑上把环路里多余的某一条边暂时阻塞掉，修剪成一棵无环的树（真断线了再自动启用备胎）；现代大型数据中心则进一步采用受控的多路径或三层化架构来避开二层大环路。

此外，如果一栋大楼里有财务部、研发部和访客 Wi-Fi，全塞进同一个巨大广播域里既不安全又吵闹。管理员可以用 **虚拟局域网**（VLAN，Virtual LAN）技术，在以太网帧头塞进一个 4 字节的 VLAN 标签（802.1Q），把同一组物理交换机在逻辑上切分成多个老死不相往来的独立广播域——即便两台电脑插在同一台交换机相邻的网口上，只要分属不同 VLAN，它们的广播就互不可见，想通信必须老老实实走三层路由器或网关过安检。

## ARP 走查与它的信任软肋

现在，把前面零散的拼图扣在一起，拿一组真实 IP 亲手走一遍跨网段访问的完整四步！

假设你的主机配置与目标如下：

```text
本机 IP：   192.168.1.10/24
默认网关：  192.168.1.1
远方服务器：198.51.100.20
```

你的主机先拿 `198.51.100.20` 与子网掩码按位与，一眼看出它不在 `192.168.1.0/24` 本地子网内，必须交给默认网关 `192.168.1.1`。假如本机内存的 **ARP 缓存表** 里此刻还没有 `192.168.1.1` 的记录，下面四步瞬间展开：

1. **广播问路**：主机封装一个目的 MAC 为 `ff:ff:ff:ff:ff:ff` 的 **ARP 请求** 广播帧，在局域网大喊：「谁是 `192.168.1.1`？请告诉 `192.168.1.10`（顺便附上我的 MAC）！」交换机泛洪给全网段设备；普通电脑一看问的不是自己便悄悄丢掉，只有默认网关 `192.168.1.1` 认领，单播回复一条 **ARP 应答** 报出自己的 MAC 地址。你的主机立刻把 `192.168.1.1 <-> 网关 MAC` 存入本地 ARP 缓存（同样带老化时间），省得下次再喊。
2. **封装内层 IP 包**：构造源 IP `192.168.1.10`、目的 IP `198.51.100.20` 的 IP 数据报。
3. **封装外层以太网帧**：源 MAC 填本机网卡地址，**目的 MAC 填刚刚问到的默认网关 MAC**，推上网线。
4. **网关拆包接力**：网关收到帧，剥掉以太网壳，查路由表找到运营商方向的下一跳，换上通往运营商设备的新帧首尾部发往远方！

然而，ARP 诞生于互信纯朴的早期局域网年代，它有一个极度危险的先天缺陷：**无状态且毫无身份认证！**

只要同局域网里混进一台怀有恶意的电脑，它甚至不需要等你发 ARP 请求，就能直接往你和网关双方疯狂发送伪造的 ARP 应答：「喂！我是网关 `192.168.1.1`，我的 MAC 是我这块网卡！」（同时告诉网关「我是 `192.168.1.10`！」）。受害主机傻乎乎地信以为真、覆盖掉本地 ARP 缓存，从此你发往外网的所有流量全都先乖乖流进攻击者的电脑，再由攻击者偷偷转给真网关——这就是臭名昭著的 **ARP 欺骗**（ARP spoofing / poisoning）与局域网中间人截获！

因此，永远不要轻信「局域网里都是自己人」。企业网通常在交换机上开启 **动态 ARP 检查**（DAI，对照前面第 5 章提过的 DHCP snooping 合法绑定表，把撒谎的伪造 ARP 帧当场拦死）、配合关键节点静态绑定和 VLAN 隔离；而对于咱们普通用户，在咖啡馆或公共 Wi-Fi 下最靠得住的终极护身符，依然是端到端的 **HTTPS / TLS**——就算底层 ARP 真被劫持，黑客抓到的也只是一堆解不开的密文。

顺带一提，新一代 **IPv6** 彻底告别了独立的 ARP 协议，也不再使用全网打扰的广播，而是把邻居地址解析、寻找本地默认路由器、检测地址冲突等功能统统收编进了基于 ICMPv6 多播的 **邻居发现协议**（NDP，Neighbor Discovery Protocol）里，功能更规整，但同样需要配套的安全防护与过滤策略。

## 从有线走进无线：Wi-Fi 接入与空口性能权衡

如果说以太网是安静规整的专用轨道，那 **Wi-Fi（IEEE 802.11）** 就是在开放电磁空域里上演的精细杂技。当你拿出手机点选一个 Wi-Fi 名称并输入密码，短短两秒内后台其实走完了五步：

1. **扫描发现**：无线接入点（AP，Access Point）像灯塔一样定期广播信标帧宣告网络名称（SSID）和支持能力；手机也可以主动发探测请求寻找周围热点。
2. **认证与关联**：手机和选中的接入点打招呼确认基础能力、商量支持的传输速率集，正式挂靠到这台 AP 名下。
3. **安全握手**：在加密 Wi-Fi（如 WPA2/WPA3）中，双方完成四次握手等密钥协商流程，把空气中飞舞的无线帧加密保护起来，防旁人直接抓包窃听。
4. **领 IP 参数**：连上二层之后，立刻触发第 5 章学过的 DHCP（或 IPv6 自动配置）领到 IP、掩码、网关和 DNS。
5. **桥接出网**：接入点在背后扮演一座**无线与有线之间的透明网桥**，把你发来的 802.11 无线帧转换成标准以太网帧送进后面的局域网或宽带网关。

很多人在家里连 Wi-Fi 时都会纳闷两件事：**第一，路由器包装盒上吹着「千兆、三千兆速率」，为什么实际测速连一半都不到？第二，明明我坐在路由器旁边信号满格，为什么室友躲进厕所刷视频时，连我这边的网都跟着一起变慢了？**

揭开 802.11 的两项底层权衡，谜底瞬间清晰：

- **空口共享 + 链路层本地 ACK + 协议开销**：无线频道是半双工共享的（同一时刻周围连着这台路由器的手机只能轮流说），加上前面学的 CSMA/CA 退避等待、每一帧都要等对端回一条链路层 ACK、信号稍有波动就触发本地重传（虽然比等端到端 TCP 重传快得多，但重传实实在在吃掉了公共空口时间），物理层标称峰值速率扣掉这些开销后，应用层实际好吞吐常常只有标称值的一半甚至更低。
- **「一颗老鼠屎」效应（低速终端霸占空口时间）**：当室友躲进信号极差的厕所，为了把帧勉强传通、不至于全丢，他的手机和路由器会自动把调制速率从几百 Mb/s 一路降档到十几甚至几 Mb/s。速率降了十倍，意味着他发同一个 1500 字节的包，占住公共无线频道的时间暴涨了十倍！他占着频道慢慢发的时候，坐在路由器旁边信号满格的你也只能干等！这就是为什么信号死角里的一台慢设备，有时能把整个房间的 Wi-Fi 体验拉下水。

频段选择同样是一场物理取舍：**2.4 GHz** 波长较长、穿墙绕射能力强、老设备通吃，但总共只有 3 个互不重叠的窄信道，而且蓝牙、微波炉、隔壁邻居路由器全挤在里面吵得不可开交；**5 GHz** 和更新的 **6 GHz** 信道极其宽敞、干扰少、吞吐飞快，代价是隔两堵承重墙信号就大幅衰减。做好无线部署，靠的是合理规划信道、选好 AP 摆放位置、确保背后有线回程不拖后腿以及控制单 AP 终端密度，远不是看一眼手机顶栏「几格信号」那么简单。

## 端到端全景小结：排障先问「卡在哪张表？」

学完第 1 章到第 6 章，我们已经亲手走通了经典五层协议栈的完整闭环！回头把沿途遇到的所有「地址与转发表」串成一条珠链，你会发现整个互联网其实清澈如水：

- **应用层（DNS 缓存表）**：把域名翻译成目标 IP；
- **传输层（操作系统 Socket 连接表 / 五元组）**：用端口号把字节交给正确进程，并用序号和窗口兜住可靠与节奏；
- **网络层（路由器 IP 转发表）**：靠最长前缀匹配，把数据包一跳一跳引向目标子网；
- **链路层（主机 ARP 缓存表 + 交换机 MAC 学习表）**：把下一跳 IP 翻译成网卡 MAC，在局域网内精准完成每一跳帧交付。

以后遇到网络故障，别再盲目重启光猫和路由器——顺着这四张表逐一检查「DNS 查对了没有？端口通不通？路由指向哪？ARP 和 MAC 学到了没有？」，几乎所有连通性疑难杂症都会现出原形。

!!! question "随堂自测"
    当二层交换机在自己的 MAC 表里查不到目的 MAC 地址时，它会果断向其他所有端口「泛洪」；可当三层路由器在路由表里查不到目的 IP 地址的匹配路由（且没有默认路由）时，它却会毫不留情地「直接丢弃」！为什么两者的反应截然相反？

    关键在于**规模边界不同**。二层交换机面对的是一个规模受控的有限本地广播域（几十到几百台设备），偶尔泛洪一次成本极低，不仅能让未知目标顺利收到帧，还能趁着对方回包顺势把它的位置学进表里；而三层路由器连接的是覆盖全球数十亿设备的广袤互联网，如果路由器查不到路由就往全世界其他所有接口泛洪，全网骨干链路一秒钟内就会被指数级复制的幽灵数据包彻底淹没。因此路由器绝不泛洪，找不到明确路由或默认兜底就必须立刻丢弃（并按策略回发 ICMP 目的不可达）。

至此，我们已经完整打通了数据从应用一路沉入网线与无线电波、再跨越全球抵达彼岸的全部机制。可回望刚才走过的每一层，一个沉甸甸的阴影始终如影随形：

- 在局域网里，ARP 毫无认证，任何人都能冒充网关把你的流量悄悄拐走；
- 在咖啡馆里，Wi-Fi 信号飘在空气中，旁边一台电脑就能静静监听；
- 在公网上，你的数据包要穿过十几个素未谋面的运营商机房，沿途任何一台被攻陷的路由器都能偷看、篡改甚至伪造你的 HTTP 明文和 DNS 回答！
