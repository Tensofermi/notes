# 链路层与局域网 { #5 }

上一章里，数据包在网络层的指挥下完成了宏大的跨网寻路：路由器查完最长前缀匹配，终于敲定了「下一跳是眼前这台相邻设备」。

可网络层只负责指方向，并不负责把字节真正变成铜线里的电压脉冲、光纤里的光束，或者空气中扩散的无线电波。数据包离开网络层后，要踏出实实在在的「眼前这一跳」——把数据封装成帧、稳稳送到同一段物理链路上的下一块网卡手里。掌管这一跳全部规矩的，就是 **链路层**（link layer）；而在家庭、宿舍、办公室或机房里把近距离设备连成一片的网络，正是我们天天打交道的 **局域网**（LAN，Local Area Network）。

比起网络层的全局视野，链路层只盯着眼前这一小段路。可恰恰就在这一小段路上，冒出了网络世界里最「看得见摸得着」的物理与协作难题：

1. **信号传错了怎么办？** 电磁干扰、墙体衰减、雷雨噪声随时可能把某个 `0` 拨翻成 `1`，接收方怎样用极少的冗余位一抓一个准？
2. **大家抢着说话怎么办？** 一间教室里几十台手机连在同一个 Wi-Fi 频道上，或者多台主机共享一根介质，大家同时开口信号就会撞成乱码，该按什么规矩排先后？
3. **只知道下一跳的 IP，怎么找到对方的网卡？** 刚插电的局域网交换机一张表都没有，怎么神奇地「自学成才」精准转发？电脑又怎么问出眼前网关的硬件地址？

互联网之所以能把光纤、双绞线、Wi-Fi、蓝牙甚至卫星无缝粘合成一体，靠的正是 IP 之下每一跳都可以自由切换最适合眼前介质的链路层技术。

## 先把一对极易混淆的缩写分清：本章的两个 MAC

读链路层时，你会高频撞见 `MAC` 这三个大写字母，它偏偏在两个完全不同的语境里都叫 `MAC`：

1. **Media Access Control（介质访问控制）**：指的是一套**说话规矩**——多台设备共享同一段信道（如同一 Wi-Fi 频段）时，决定谁什么时候发、撞车了怎么退让。
2. **MAC Address（MAC 地址 / 硬件地址）**：指的是网卡在局域网里的**门牌编号**（常见为 48 比特，如 `00:1a:2b:3c:4d:5e`），用来在一跳交付时写清「哪块网卡发的、交给哪块网卡」。

两者同属链路层、息息相关，却绝不是同义词——前者是「交通规则」，后者是「车牌号」。把它们提前分清，后面读起来就绝不会犯迷糊。

2. 面对共享信道，信道划分、随机接入和轮流接入各自在低负载和高负载下表现如何？
3. 一台刚拆箱通电的二层交换机，没做任何配置，是怎样一步步「自学」出整张转发表的？
4. 当你的电脑访问千里之外的网站服务器时，它在本地局域网发出的 ARP 广播究竟在问谁的 MAC 地址？
5. 为什么 Wi-Fi 宁可费劲搞退避和预约，也没法像早期有线以太网那样简单地「边发边检碰撞」？

!!! question "出发前先猜一道经典题"
    当你在家里用笔记本访问远在异地的某台网站服务器时，电脑在本地局域网发出的 ARP 广播，查询的是那台远方网站服务器的 MAC 地址吗？

    当然不是！MAC 地址和 ARP 广播的作用范围仅限于你家这片本地局域网。既然电脑通过子网前缀判断出网站服务器远在外网，它这一跳必须把帧先交给家里的默认网关——因此它发出的 ARP 查询问的是**默认网关的 MAC 地址**，而不是远方服务器的地址。
