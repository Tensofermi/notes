# HTTPS、SSH 和 VPN 分别管哪段连接

远程访问可以发生在三个位置：浏览器打开网页时，可以用 HTTPS 保护网页请求；在另一台机器上输入命令时，可以用 **SSH** 建立受保护的远程终端连接；需要让设备经现有网络加入一个虚拟私有网络时，可以用 **VPN**。下面沿同一次操作看每一段。

## 一条远程操作穿过了几道身份检查？

假设先连私有网络，再用 SSH 登录到工作站，最后读取 `/project/result.txt`。私有网络决定这个设备能否到达工作站。SSH 验证服务与登录身份。文件访问还要由工作站的内核按进程身份检查权限。把各道关口画出来，就能明白换了一个接入方式为什么不必自动多拿文件权限。

??? question "VPN 能到工作站、SSH 也成功，但文件拒绝读取，先查什么？"

    先查远端运行的实际身份、文件所属组和目录访问权限。这次错误发生在已经连通、并已成功登录之后。

**先修**：[TLS 与可信连接](01_tls.md)、[基本威胁与分层防御](02_threats_defenses.md)。

**读完能做**：为一次远程操作画出连接和身份检查的边界。

## 同一台工作站，三种入口

| 入口 | 保护的范围 | 仍要核对 |
| --- | --- | --- |
| HTTPS | 浏览器或 API 客户端与 TLS 端点之间的连接 | 服务器名、证书、应用身份，以及代理之后的链路 |
| SSH | 客户端与 SSH 服务之间的远程登录或转发会话 | 主机密钥、登录身份、能执行的命令或访问的资源 |
| VPN 或私有覆盖网络 | 按其配置接入的网络连接或隧道 | 获准访问哪些目标、目标应用自己的认证和授权 |

假设运维人员通过私有网络进入工作站。私有网络准许某个设备访问这台机器，SSH 再验证登录方和主机身份；用户在 shell 中读取任务目录，内核还要检查文件权限。给工作进程读取数据的凭据应与远程登录凭据分开管理，避免一个权限失效影响另一条路径。

## 先认清 TLS 终止在哪里

浏览器与反向代理建立 HTTPS，代理再发请求给后端。客户端验证的是自己连接的 TLS 端点。代理到后端如果需要加密和认证，应按这一段的独立边界配置。日志可记录请求 ID、身份与结果，用于审计；凭据与敏感输入应控制披露范围。

## 自测

你已在 VPN 里，但操作系统返回「没有权限读文件」。哪一层已通过，哪一层拒绝了请求？

??? note "参考思路"
    在已经成功登录的场景中，网络连通和远程登录已经建立。读文件还要检查该进程的身份、挂载和操作系统权限。要给任务开通权限，可以只开放所需文件与操作。
