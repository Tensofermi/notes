# 综合练习：从远程请求到 Agent 沙箱

**先修**：[虚拟网络](../chapter_09_virtual_network/01_interfaces_bridges_tunnels.md)、[服务发现与代理](../chapter_09_virtual_network/02_service_discovery_proxies.md)、<a href="../../OperatingSystems/chapter_06_protection_virtualization/01_protection_security.html">操作系统的保护机制</a>。

**目标**：能从用户请求追到执行进程，说明故障与权限分别在哪一层处理。

## 先把一次请求画出来

假设一台云 VM 上运行任务 API。用户可以经 Dashboard 或消息入口提交任务；开发者可以用 SSH 或远程编辑器连接工作站。假设管理网络通过私有覆盖网络接入。它们都是入口，实际执行沿任务 API、状态存储、工作进程和沙箱展开。

```text
用户 → Web 或消息入口 → TLS/代理 → 任务 API → 有限队列 → 工作进程 → 沙箱进程
                                    ↓                    ↓
                             任务状态和身份          挂载目录、结果和日志
```

一次提交应能找到任务 ID 和提交者。长任务可通过状态接口查询；浏览器断开，只要独立的任务和工作进程仍在，执行可以继续。VM 重启后的恢复取决于是否持久化了任务状态、挂载数据和恢复点。SSH 会话、工作进程与沙箱的生命周期要分别考虑。

## 逐层找证据

| 现象 | 第一份证据 |
| --- | --- |
| 服务名无法解析 | 客户端实际使用的名字、DNS 与解析结果 |
| 有地址但 TCP 无法建立 | 客户端路由、目标监听和访问控制 |
| 代理能返回错误但任务未创建 | HTTP 响应、请求 ID、代理与 API 日志 |
| 任务已入队但未执行 | 队列长度、等待时间和工作进程状态 |
| 沙箱不能读取输入 | 运行身份、挂载路径、文件权限和可用凭据 |
| 重启后任务没有结果 | 尝试 ID、持久目录与最后一份可恢复状态 |

日志记录一次事件，指标用于看总体走势，追踪把有共同标识的请求步骤连在一起。一次请求和一次任务可能各有自己的 ID；记录二者关系，才能从入口追到后来异步执行的任务。用失败率、队列等待时间和延迟分位数观察变化；避免把每个任务 ID 放进指标标签或把密钥写入日志。

## 本机实验与纸面推演

1. 运行[本机 HTTP 服务实验](../chapter_02_application/04_socket_and_listening.md)，先访问可用端口，再访问一个空闲端口以及一个不存在的资源。记录连接失败与 HTTP 404 的区别。
2. 假设代理能访问 API，但沙箱没有挂载工作目录。分别写出请求层与执行层会留下的证据。
3. 假设工作进程被重启。把只在进程内存、只在容器可写层、已经存入持久目录的三类数据分别放到一张恢复表。
4. 给沙箱设计最小可运行权限：需要读取哪些输入、写到哪、能否出网、需要哪个短期凭据。用任务 ID 关联诊断记录。

进一步学习见 [OpenTelemetry 可观测性入门](https://opentelemetry.io/docs/concepts/observability-primer/)。
