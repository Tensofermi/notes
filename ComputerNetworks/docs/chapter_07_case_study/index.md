# 第7章 综合案例

前六章为了学习而分层，本章把层次重新叠起来。目标不是背一条永远不变的报文序列，而是掌握一条可解释、可验证的因果链：每一步需要什么前置状态，产生什么新状态，失败时会看到什么现象。

## 本章内容

- [从输入 URL 到页面出现](01_url_to_page.md)：以一次新的 HTTPS 访问为主线，经过名称解析、路由选择、邻居解析、传输握手、TLS、HTTP、服务端处理和浏览器渲染。

## 为什么综合案例重要

现实故障不会标注“这是第三层问题”。用户只会说页面打不开、很慢或证书报错。只有把完整路径放在脑中，才能把现象拆成可验证问题：

```text
名称解析了吗
  -> 有可用路由吗
  -> 下一跳可达吗
  -> 端口握手完成吗
  -> TLS 身份验证通过吗
  -> HTTP 返回什么
  -> 浏览器为何仍未渲染
```

## 场景假设

案例使用一台通过 Wi-Fi 接入家庭网络的笔记本，访问 `https://www.example.com/`。为展示完整机制，假设 DNS、ARP 和 HTTP 缓存最初均未命中，并以 HTTP/2 over TCP 为主。真实浏览器可能选择 IPv6、HTTP/3、已有连接或 CDN 边缘，所以抓包不一定与示意完全相同。

!!! tip "阅读方法"
    每读一步都标出四件事：当前设备、所处协议层、使用的标识符、产生的新缓存或连接状态。这样可以把长流程压缩为少数状态转换。
