# 诊断与复习 { #8 }

无论你是在宿舍帮同学修电脑，还是半夜三点被线上告警电话吵醒，听到的第一句话往往都同样令人抓狂——「网挂了！」「网页打不开！」「接口连不上了！」

这句模糊的抱怨根本没法直接动手修，但经过前面十章和刚走完的两条综合链路训练，你现在一眼就能把它精准剖开成至少四个彼此独立、可以逐一核实的硬问题：

1. **名字查对了吗？** 域名到底有没有解析成预期的目标 IP？
2. **路通吗、门敲开了吗？** 路由和防火墙有没有放行，目标端口上的 TCP 或 QUIC 握手到底成没成？
3. **身份验过了吗？** TLS 证书链、域名和有效期有没有翻车？
4. **服务怎么回答的？** 应用层究竟返回了 `200`、`404`、`503`，还是压根卡死超时？

网络排障绝不是慌乱地把背过的几十条命令挨个盲敲一遍，再顺手重启所有路由器碰运气。**高手的诊断是用最少、最省事的观测动作，一口气排除掉最多错误假设！**

## 像科学家一样排障：一套通用六步闭环

优秀排障和做物理实验遵循完全相同的科学方法。只要遇到疑难杂症，立刻把下面这六步闭环套上去：

```text
1. 准确量化描述现象（绝不止于「连不上」）
   -> 2. 建立最小、可重复的复现方式（把浏览器换成一条 curl）
      -> 3. 提出一个清晰、可证伪的假设
         -> 4. 挑出最有区分力、成本最低的一条观测命令
            -> 5. 根据拿到的硬证据砍掉一半搜索空间
               -> 6. 精准修复后复测验证，并留下复盘记录
```

对比一下「外行描述」和「专业故障描述」的巨大差距：
- 外行描述：「线上 API 炸了，网不通！」——信息量几乎为零，接手的人无从下手。
- 专业描述：「从 14:20 起，我这台 Mac 通过 `dig` 解析 `api.example.com` 正常返回 `203.0.113.5`，但 `nc -vz` 连接 `203.0.113.5:443` 持续超时；奇怪的是，连在同一个 Wi-Fi 下的另一台手机访问同一个地址却完全正常！」

瞧见魔力了吗？短短两句话里，已经清清楚楚打包了**发生时间、客户端环境、已排除 DNS 嫌疑、明确卡在 TCP 443 超时、外加一条极有价值的同网对照组**——故障瞬间从「漫无边际的互联网」被死死锁进了「这台 Mac 本机路由/代理/防火墙，或者该 IP 针对特定源端的策略」这一丁点范围内！

## 刻在手腕上的三条排障铁律

在按下键盘执行任何修复动作前，先默念这三条救命纪律：

1. **先定范围，再抠细节**：先搞清楚遭殃的是一台电脑、一个进程、一片局域网子网、某一家宽带运营商，还是全球所有用户？范围定对了，一半无关线索瞬间出局。
2. **先留证据，绝不急着重启**：很多人一急就习惯重启服务或重启光猫——重启固然偶尔能「歪打正着」让业务暂时恢复，可它也在一秒钟内彻底销毁了内存连接表、路由状态和进程现场！下次半夜三点同样的问题卷土重来，你依然两眼一抹黑。
3. **每次只改一个变量**：如果你一口气同时换了 DNS 解析器、关了本机防火墙、改了端口又重启了代理，哪怕突然通了，你也永远不知道真正起作用的究竟是哪一刀，甚至可能顺手埋下新的安全隐患。

!!! warning "合法合规与隐私红线"
    切记**只对自己拥有明确授权管理的网络、主机与测试环境**执行扫描和抓包操作。网络抓包文件（`.pcap`）里可能直接包含明文 Cookie、查询域名、源目 IP 和敏感业务载荷——抓包时务必写明最小精确过滤表达式，按最小权限妥善保管，排障复盘结束后第一时间彻底清理删除。
