# 第8章 诊断与复习

网络排障不是把所有命令都运行一遍，而是用最少观测排除最多假设。好的诊断过程记录时间、对象、预期和实际结果，并从范围最小、成本最低的检查开始。

## 本章地图

- [诊断工具与排障路径](01_diagnostic_tools.md)：从本机配置到 DNS、端口、TLS、HTTP、路由与抓包。
- [自测题与答案](02_review_self_test.md)：覆盖概念、计算和综合场景。

## 一个通用闭环

```text
准确描述现象
  -> 建立最小复现
  -> 提出一个可证伪假设
  -> 选择能区分结果的观测
  -> 根据证据缩小范围
  -> 修复后复测并记录
```

“网络不通”不是可操作描述。更好的描述是：“这台 Mac 从 14:20 起解析 `api.example.com` 正常，但连接 `203.0.113.5:443` 超时；同一 Wi-Fi 上另一台设备正常。”它已经提供时间、客户端、DNS、传输端口和对照组。

## 三个排障原则

1. **先范围后细节**：一台设备、一个网段、一个地区还是所有用户？
2. **先证据后改动**：重启可能暂时清除状态，也会销毁现场。
3. **一次只改变一个变量**：同时换 DNS、关防火墙和重启路由器，成功后也无法知道根因。

!!! warning "合法与隐私"
    只抓取和测试自己有权管理的网络。抓包可能包含 Cookie、域名、地址和业务数据，应使用最小过滤范围，妥善保存并及时删除。
