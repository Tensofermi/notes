# 从虚拟网卡到隧道：一条容器网络路径

**先修**：[地址和子网](../chapter_04_network/01_ip_addressing_subnetting.md)、[NAT](../chapter_04_network/02_ipv6_nat_icmp.md)、[以太网和 ARP](../chapter_05_link/02_ethernet_wifi_arp.md)。

**读完能做**：区分虚拟网卡、网桥、路由、NAT、隧道与加密分别改变了什么。

## 给隔离的进程接网线

网络 namespace 可以有自己的接口、路由表和端口空间。Linux 的 veth 是成对的虚拟以太网设备，一端发出的帧能从另一端收到。把一端交给容器，另一端接到宿主机，就得到一段可观察的虚拟连接。把多个宿主机端口接入同一网桥，可以像用二层交换机那样转发帧。

假设 A 地址为 10.20.0.2，B 为 10.20.0.3，都在同一个 10.20.0.0/24 子网的教学网络里。A 向 B 发包时，先确定目标在本地子网，再通过 ARP 得到 B 的链路地址；帧经 veth 进入网桥，网桥转发到 B 那一侧。如果目标不在本地子网，A 会尝试交给路由表指定的下一跳。需要访问外部时，宿主机可以做路由转发；是否做源地址转换取决于网络配置。

## 从一台宿主机扩展到两台

两台宿主机可能只有底层 IP 网络连通。隧道把内部包封装进外部包，外层地址用于到达隧道对端，解封装后继续处理内部地址。逻辑网络建立在现有网络之上，称为覆盖网络。封装增加头部开销，因而需要考虑有效 MTU、网络诊断位置和额外的数据路径。隧道可以配合加密，也可以只封装。

| 要解决的问题 | 对应机制 |
| --- | --- |
| 容器各自有接口、端口和路由表 | 网络 namespace |
| 连接两个虚拟接口 | veth 对 |
| 同一二层网络内转发帧 | 网桥 |
| 跨子网按目标前缀转发 | 路由 |
| 变更地址或端口并在返回时匹配 | NAT |
| 在现有网络上传输另一套逻辑网络的数据 | 隧道与覆盖网络 |
| 要求链路上的中间节点看不到明文 | 加密协议 |

远程访问工作站时，若节点都没有可直接接收入站连接的公网地址，可以考虑受控的覆盖网络。NAT 状态、连接发起方向和网络策略决定直连是否可行；必要时经中继可达，代价是路径更长且吞吐受中继限制。Tailscale 是一个应用例子。能经虚拟网络到达服务，应用端仍需按自己的规则认证与授权。

## 自测

如果同一宿主机上的两个容器可以互访，但不同节点的容器间只有小请求成功，大响应超时，你会检查哪两项？

??? note "参考思路"
    检查跨节点流量实际走哪条路径，以及封装后有效 MTU 和相关反馈是否正常。也要结合抓包位置与 TCP 重传判断，避免直接把所有超时归因于 MTU。

延伸见 [Linux veth](https://man7.org/linux/man-pages/man4/veth.4.html)与 [Tailscale 连接类型](https://tailscale.com/kb/1257/connection-types)。
