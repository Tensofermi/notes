# 数据中心互连：从两台机器到集合通信

**先修**：[网络性能](../chapter_01_foundations/02_packet_switching_and_performance.md)、[转发与路由](../chapter_04_network/03_forwarding_routing.md)。

**读完能做**：区分链路或网络、数据搬运机制以及分布式通信操作，估算一次多机通信的时间量级。

## 为什么加机器有时没加速

两台机器分别处理一半输入，如果完全独立，可以接近同时完成。同步训练中，各机器常需交换本地计算结果，再进入下一步。每步的时间除了计算，还包括准备通信、搬运数据、等待慢节点与同步。把 256 MB 通过有效吞吐 25 GB/s 的路径发出去，单次传输仅按数据量计算约需 10.2 ms。这个估算以十进制单位计，尚未包括路径争用、协议调度和同步。

## 三个层次

| 层次 | 例子 | 重点问题 |
| --- | --- | --- |
| 设备与网络 | 网卡、交换机、以太网、InfiniBand | 哪些节点共享链路，拥塞和故障在哪里 |
| 数据移动机制 | 常规 Socket、RDMA | 发送和接收需要多少主机软件参与，缓冲区如何准备 |
| 集合通信 | Broadcast、AllReduce、AllGather | 哪些进程参与，各自最终得到什么数据 |

RDMA 可让支持的设备按约定访问已注册的内存，减少某些数据路径上的主机 CPU 参与和拷贝。它需要合适的网卡、驱动、缓冲区管理和网络配置。InfiniBand 是一种互连技术，支持 RDMA；以太网上也有承载 RDMA 的方案。多机传输的瓶颈可能在设备、链路、拓扑或通信算法，测量时应交代参与节点和消息大小。

## 手算一次 AllReduce

两个工作进程各有一个向量，A 为 `[1, 2]`，B 为 `[3, 4]`。以求和做 AllReduce 后，每个进程都得到 `[4, 6]`。若训练用平均梯度，可以在应用约定的相应位置除以参与数。节点增加以后，可以选择不同的通信拓扑与分步方式，权衡传输量、同步轮数和慢链路。

??? note "参考思路"
    看各进程的计算时间和抵达同步点的先后、集合通信的消息大小与耗时，以及跨节点链路和网卡的负载。等待还可能由某个进程的数据准备慢造成。
