# 抽象层次与接口契约

## 同一行加法，在每一层看见什么？

我们写 `total = count + 1`。语言规定变量的类型和加法结果。为了让处理器执行这行代码，编译器把它转换成一条条**机器指令**。其中的加法指令要指定从哪个**寄存器**读 `count`，再把结果写到哪里。寄存器是处理器内部少量能直接读写的位置。到了电路层，设计者关心这些值是怎样用 0 和 1 表示、又怎样在部件之间传递的。两台处理器可以用不同数量的步骤完成同一条指令，只要软件看到的是同样的结果。

??? question "换一个更快的缓存，通常需要重写这条机器指令吗？"

    缓存是处理器附近一小块用于暂存常用数据的快速存储。只要处理器仍能认出同一条指令、给出约定的结果，原先编译出的代码就能继续运行，耗时可能会变。

## 动机：复杂性必须被切开

数十亿晶体管不可能由应用程序员逐个控制。工程上的办法不是消灭复杂性，而是建立边界：上层只依赖下层承诺的行为，下层可以在不破坏承诺的前提下更换实现。这就是抽象。

共同遵守的指令规则叫**指令集架构**（ISA），处理器内部执行这些规则的方式叫**微体系结构**。例如，一台机器可以把指令的几个步骤安排得像生产线，这叫**流水线**。它也可以把常用数据留在离处理器较近的快速存储里，这就是**缓存（cache）**。把这些概念放回各层，可以画成下面这样。

```text
应用与算法
  ↓
高级语言、编译器、操作系统
  ↓
指令系统结构 ISA
  ↓
微体系结构：数据通路、控制、流水线、cache
  ↓
数字逻辑：门、组合电路、时序电路
  ↓
器件与工艺：晶体管、连线、存储单元
```

各层也会从下向上传递信息。如果指令遇到无法访问的地址，处理器可以暂停这条指令，向操作系统报告原因。这类由指令触发的事件叫**异常**。硬件还可以用**性能计数器**记录某类事件发生的次数，例如所需数据没在缓存中（未命中）的次数。

## 接口与实现

**接口**说明使用者可依赖什么，**实现**说明承诺怎样兑现。以加法指令为例，ISA 会规定操作数来自哪些寄存器、结果保留多少位，以及保存下一条指令地址的**程序计数器**如何变化；它通常不规定这次加法由一拍完成、分成多级流水，还是在保持软件可见行为的前提下让后到的指令先执行，这叫**乱序执行**。

这带来两个好处：

- 软件生态可跨处理器代际复用；
- 硬件设计者可以用面积、功耗和性能之间的不同权衡实现同一语义。

代价是接口一旦广泛部署就很难修改。历史兼容性会让旧指令、旧异常行为和旧地址模式长期存在。

## 最小完整例子：`z = x + 1`

假设 `x` 和 `z` 位于内存，寄存器 `x10` 存着 `x` 的地址，`z` 紧跟在它的 4 字节之后。`lw` 从内存读一个 32 位数，`addi` 给寄存器里的值加上指令中写明的常数，`sw` 把一个 32 位数写回内存。先按这个意思读三条简化指令。

```asm
lw   x5, 0(x10)   # x5 <- Mem[x10]
addi x5, x5, 1
sw   x5, 4(x10)   # Mem[x10 + 4] <- x5
```

各层分别做什么？

| 层次 | 对这个例子的职责 |
| --- | --- |
| 语言 | 规定整数加法和溢出的语言语义 |
| 编译器 | 选择 `lw/addi/sw`，分配寄存器 |
| ISA | 规定三条指令的编码与可见效果 |
| 微体系结构 | 取指、译码、计算地址、访问 cache、写回 |
| 数字逻辑 | 用加法器、多路选择器、寄存器和状态机实现数据流 |
| 器件 | 在电压、时序和功耗约束下实现逻辑 0/1 |

这里的加法要等读取完成，写回内存又要等加法给出结果。如果读取还没命中缓存，后两步就可能等得更久。[一条 load/add/store 如何贯穿机器](../chapter_08_case_study/load_add_store_walkthrough.md)会按处理器的时钟一拍一拍展开这个过程。

## 架构状态与瞬时状态

**架构状态**是指令规则规定软件能看到的值，例如 `x5` 加 1 的结果和 `z` 更新后的内容。为了加速，处理器还会保存临时结果等**微体系结构状态**。例如遇到条件跳转时，处理器可以先猜下一条指令在哪，提前算出一些结果。猜错时可以丢掉这部分临时结果。把指令的结果确认为程序可见的进展，这一步叫**提交**。

可以把提前算出的值看作写在草稿纸上的答案。只有确认这条指令应该执行，才会把值当作正式结果交给软件。

## 抽象会泄漏

同一个二维数组，按行或按列都可以读遍所有元素，但按行连续访问时，下一项更可能已经随相邻数据一起进入缓存。这叫**空间局部性**，它能让两种写法的耗时明显不同。[缓存块算例](../chapter_06_memory/hierarchy_cache.md)会逐次验证哪些读取能复用同一块数据。

因此更准确的直觉是：抽象建立**可依赖的最低契约**，而不是让下层永远不可见。

## 与其他课程的联系

- 数据结构讨论访问模式，组成原理解释访问模式为何影响 cache。
- 编译原理把高级程序映射到 ISA，并做机器相关优化。
- 操作系统管理异常、中断、页表和设备，但依赖硬件提供机制。
- 数字电路提供组成部件，组成原理解释部件怎样构成可编程机器。
