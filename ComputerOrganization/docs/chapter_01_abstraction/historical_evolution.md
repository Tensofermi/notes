# 计算机体系结构的历史演进

## 两台机器每秒的时钟数相同，速度会相同吗？

处理器的时钟给部件协调动作提供节拍。一秒有多少拍，就是**时钟频率（clock frequency）**，一拍的时间叫**时钟周期（clock period）**。假设旧机器每条指令平均用 4 拍，新机器平均用 2 拍，且两台机器的时钟频率和指令数都相同——新机器只需原来一半的时间。所以比较机器时，除了频率，还要问需要执行多少条指令、每条指令平均用几拍。答案已经藏在这个例子里：频率相同，速度未必相同。

??? question "如果新机器为了使用简单指令，指令数也翻倍，会怎样？"

    指令数增加一倍、每条平均周期减半，两者相抵。比较具体应用需要一起看指令数、平均周期和每周期时间。

历史不是型号年表，而是观察“瓶颈如何迁移”的实验记录。每一代设计都在解决当时最昂贵的问题，同时把新的复杂性推到下一代。

## 从专用接线到存储程序

早期机器换一件任务，常常意味着重新接线、拨动成排的开关——「编程」是对硬件动手术。**存储程序（stored-program）**思想把指令也编码为内存中的数据，CPU 依次取指和执行即可。程序由此可以被加载、复制和修改，通用计算机才真正成为软件平台。

在**冯·诺依曼结构（von Neumann architecture）**中，指令和数据共用一条通往内存的路。这条路每秒能运来的字节数有限，数据来不及运时就会拖慢计算，这叫**冯·诺依曼瓶颈（von Neumann bottleneck）**。应对办法是把常用数据留在缓存里、猜到稍后要用的数据就提前读取（这叫**预取（prefetch）**），或者干脆加宽传输通道。瓶颈没有消失，只是被一再推远——这个模式会在后面的历史里反复出现。

## 集成电路与微处理器

真空管被晶体管替代后，器件更小、更可靠；**集成电路（integrated circuit，IC）**又把大量器件和连线放到同一块芯片上，**微处理器（microprocessor）**则把整颗 CPU 集成进单芯片。成本骤降，个人计算和嵌入式系统迅速扩张。

**摩尔定律（Moore's law）**描述可经济集成的晶体管数量长期增长的趋势，**Dennard 缩放（Dennard scaling）**曾保证晶体管变小后功耗密度大致可控。在这两者的红利期，设计者只需提高频率、加深流水线、增加复杂执行单元，就能让单线程性能持续提升。可是，如果红利消失了怎么办？

## RISC 与 CISC 的争论

存储昂贵、编译器能力有限的年代，让一条指令能做多个动作，程序就可能用更少的字节表达同样的工作——这是**复杂指令集计算机（Complex Instruction Set Computer，CISC）**的出发点之一。相反的一派主张：让编码更规则，算术只用寄存器里的数据，内存读写分别交给 `load` 和 `store`，硬件就很容易从指令位中识别下一步该做什么。这是**精简指令集计算机（Reduced Instruction Set Computer，RISC）**。

两种思路现在常共存。遵循 x86 指令规则的处理器可以把复杂指令拆成内部的小动作。RISC-V 也可以用较短的编码表示一些常用指令。继续读[两种设计的取舍](../chapter_03_isa/assembly_risc_cisc.md)，可以问同样的工作是由编译器拼出指令序列，还是在处理器里拆开执行。

## 功耗墙与多核转向

频率越高，动态功耗通常越大：

$$
P_{dynamic} \approx \alpha C V^2 f.
$$

其中 $\alpha$ 是翻转活动因子，$C$ 是等效电容，$V$ 是电压，$f$ 是频率。Dennard 缩放失效后，电压不再容易随工艺同步下降，继续拉高频率就撞上了散热与能效的极限——这堵墙被称为**功耗墙（power wall）**。于是芯片把更多晶体管投向多核、更大 cache、向量单元和专用加速器。

这次转向的代价是并行性被推给软件：两个核心并不自动让串行程序快两倍，数据划分、同步和一致性成为新瓶颈。

## 从通用到领域专用

如果一张图的每个像素都要做同样的变换，就可以让很多执行单元同时算。**图形处理器（Graphics Processing Unit，GPU）**正适合这类规则的并行工作。专门处理矩阵等多维数组的**张量处理器（Tensor Processing Unit，TPU）**，以及专门处理视频格式的电路，也是同一思路的例子：把芯片面积更多留给常用运算，减少通用控制。

适用条件是工作负载足够稳定、并行结构清晰、数据搬运可控。若算法频繁变化或控制流高度不规则，专用化收益会被开发成本和低利用率抵消。

## 一条演进规律

改进不会消灭成本，只会移动成本：

- 流水线提高吞吐量，但引入冒险；
- cache 隐藏主存延迟，但引入一致性和不可预测性；
- 多核增加算力，但引入通信与同步；
- 专用加速提高能效，但牺牲通用性。

理解这条规律，比记住某代 CPU 的参数更能迁移到未来架构。
