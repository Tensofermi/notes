# 抽象层次与整机视角 { #1 }

## 先把软件的问题和机器的问题对上

用[一条加法](abstraction_layers.md)分清源程序、指令和电路分别在描述什么，再用[两台机器的时钟与指令周期](historical_evolution.md)练习比较性能。读完能说明为什么兼容同一指令集的机器仍可以设计得很不一样。

一台计算机同时是电子系统、数字电路、指令执行器和软件平台。若一次把所有细节摊开，任何问题都会变成不可管理的网；抽象层次的作用，是让每一层只承诺稳定接口，把实现选择藏在接口之后。

## 本章动机

假设程序的加法得到了意外结果。先检查数值是否超出了源程序约定的范围，再检查编译器生成了什么指令，以及处理器有没有按约定执行。若结果正确、只是更慢，则可以问数据是否在较近的缓存里，或程序是否在等设备。分层之后，每次可以先核对一层的承诺。

## 内容

- [抽象层次与接口契约](abstraction_layers.md)用一次加法区分指令集架构（ISA，也就是软硬件共同遵守的指令规则）和处理器内部的执行方法。
- [计算机体系结构的历史演进](historical_evolution.md)从把程序存进内存谈起，看硬件设计怎样应对速度、功耗和数据传输的限制。

## 三个贯穿问题

1. **软件能观察到什么状态？** 一条指令执行过后，软件能检查寄存器和内存中的值。指令集规定了这些值怎样变化，这些可见的值属于**架构状态**。
2. **实现可以自由改变什么？** 同一份指令可以在缓存大小不同的处理器上执行。不同处理器也可以把它拆成不同数量的步骤。
3. **性能由谁限制？** 可能是一次计算花得太久，或设备来不及搬运数据。

!!! tip "学习抓手"
    每遇到一个新机制，先写出输入、输出和它记住的值，再问「哪些条件始终必须成立」。带着这四个问题去看内部细节。
