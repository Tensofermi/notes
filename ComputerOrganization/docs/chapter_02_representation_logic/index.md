# 信息表示与数字逻辑 { #2 }

## 同一串 `1111`，究竟是 15 还是 −1？

打开内存里的一小格，里面静静躺着四个二进制位：`1111`。如果现在问你，这四个位代表的数是多少，你会怎么回答？

有人说它是 $15$，有人说它是 $-1$。其实，两个答案都对，也都不对——**位串本身没有任何天生含义，真正赋予它含义的，是读取它时双方约定的解释规则。** 就像纸上写着 `10`，在十进制里是十，在二进制里是二，在十六进制里是十六；离开了解释规则，芯片里的电压高低不过是一串毫无意义的电平。

现实世界里充满了各种各样的信息：正整数、负整数、极小的物理常数、天文数字、英文字母、中文汉字，甚至还有程序指令本身。可硬件底层极其「偏食」——晶体管开关只认识两种稳定状态，记作 `0` 和 `1`。第 2 章要解开的，正是这道横亘在人类世界与硅片世界之间的翻译题：**有限长度的 0 和 1，究竟是怎样精确（或近似）地装下万千信息的？**

## 贯穿这两章的两条主线

为了把「信息表示」和紧随其后的「数字逻辑」串成一个整体，不妨记住下面两条相辅相成的主线：

1. **编码（encoding）**——解决「位模式是什么意思」。我们在数学对象（数字、符号、指令）与有限位串之间建立映射。不同的编码方案直接决定了数值范围、精度误差、电路做加减法的难易程度，以及遇到溢出和非法运算时的表现。
2. **状态（state）**——解决「位模式怎样流转并被记住」。纯粹的运算电路只根据此刻的输入立刻给出输出，没有丝毫记忆；只有引入受时钟节拍控制的存储电路，机器才能记住上一步算出的结果，也才有了地方存放「下一条该去哪个地址取指令」——也就是第 1 章提到的**程序计数器**（PC）。

## 一个最小例子：8 个 `1` 的四种身份

在深入细节之前，先看一眼 8 位全 1 的位模式 `11111111`。它在硬件里就是八个完全相同的高电平，但放进不同的上下文里，会立刻摇身一变：

- 按 **8 位无符号整数**解读，它是 $255$；
- 按 **8 位二进制补码**解读，它是 $-1$；
- 按某些 **单字节扩展字符编码**解读，它可以代表一个特定符号（例如 Latin-1 中的 `ÿ`）；
- 如果它恰好落在一段 **机器指令的位段**里，既可能是某种操作码，也可能直接代表一个参与计算的负常数偏移量。

硬件从不追问这 8 个位「本来是什么」——它只管老老实实保存位串，并按当前指令指定的电路规则去做变换。真正决定它们身份的，始终是软硬件之间约定的接口契约。
