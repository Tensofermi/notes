# 最小汇编程序与 RISC/CISC

## 从三条汇编读出谁依赖谁

假设 `x10` 是一个数组的起始地址，`lw x5, 0(x10)` 取第一个 32 位整数，`lw x6, 4(x10)` 取第二个，`add x7, x5, x6` 再相加。读这类代码时，先标出哪些寄存器里是地址、哪些装着数据，再把读和写关联起来。第三条指令需要前两条读取的结果，这种先后约束叫**数据相关（data dependence）**，它后面会反过来影响流水线的设计。

??? question "把第二个偏移改成 8，会读取第几项？"

    每项占 4 字节，偏移 8 对应下标 2，也就是第三项。程序需要保证数组中确实有这一项。

处理器实际读的是机器码，也就是一串位。**汇编语言（assembly language）**用 `lw`、`add` 之类容易记的名字表示操作，这些名字叫**助记符（mnemonic）**；某个位置也可以写成 `loop` 之类的**标签（label）**，由**汇编器（assembler）**替我们计算它对应的跳转位置。

## 最小完整程序

目标是计算 `c = a + b`。约定 `x10` 保存 `a` 的地址，`a`、`b`、`c` 依次占 4 B：

```asm
lw  x5, 0(x10)    # x5 <- a
lw  x6, 4(x10)    # x6 <- b
add x7, x5, x6    # x7 <- x5 + x6
sw  x7, 8(x10)    # c <- x7
```

假设初始状态为：

```text
x10 = 0x1000
Mem[0x1000] = 20
Mem[0x1004] = 22
```

逐条执行后：

| 时刻 | x5 | x6 | x7 | Mem[0x1008] |
| --- | ---: | ---: | ---: | ---: |
| 初始 | 未指定 | 未指定 | 未指定 | 未指定 |
| 第 1 条后 | 20 | 未指定 | 未指定 | 未指定 |
| 第 2 条后 | 20 | 22 | 未指定 | 未指定 |
| 第 3 条后 | 20 | 22 | 42 | 未指定 |
| 第 4 条后 | 20 | 22 | 42 | 42 |

这就是架构语义：四条指令、四次可见状态的更新。真实 CPU 可以让多条指令重叠执行，但不能让 `add` 使用尚未得到的旧值，也不能在异常时留下错误的已提交状态。直线执行会读了，可真实程序还要绕圈——循环怎么写？

## 一个带循环的例子

把长度为 `x11` 的 32 位数组求和，`x10` 指向首元素。`addi` 加上指令里写明的常数，`beq` 在两个值相等时跳到指定位置，下面的 `jal x0` 可直接理解为无条件跳回 `loop`。

```asm
    addi x5, x0, 0      # sum = 0
loop:
    beq  x11, x0, done
    lw   x6, 0(x10)
    add  x5, x5, x6
    addi x10, x10, 4
    addi x11, x11, -1
    jal  x0, loop
done:
```

`x0` 恒为零，省去“加载常数零”的指令。循环里的 `add` 要等前一句 `lw` 读到元素才能用，这个先后关系叫**读取后立即使用（load-use）**。跳到 `done` 则要先看 `x11` 是否为零，这类按条件决定下一条执行位置的指令叫**条件分支（conditional branch）**。短短八行，循环、判断、访存、算术全齐了——指令集的设计者要服务的，正是这样的日常。

## RISC 的设计动机

**精简指令集（RISC）**的设计倾向如下。

- 规则、较固定的指令格式；
- load/store 结构，算术主要在寄存器间进行；
- 较少而清晰的寻址方式；
- 让常用简单操作走快速路径；
- 把复杂序列交给编译器组合。

好处是译码和流水化容易、验证边界清晰。代价是某些任务需要更多指令，代码密度和取指带宽可能受影响。

## CISC 的设计动机

**复杂指令集（CISC）**兴起时内存昂贵、编译器能力有限，复杂指令可用更少机器码表达高级操作，提供丰富寻址方式，并保持早期软件兼容。

它的优点是代码紧凑、单条指令表达力强；代价是变长译码、复杂异常边界和实现验证更困难。但“复杂指令必然慢”并不准确：高频复杂指令可由专门的快速路径实现，冷门指令也可借助**微码（microcode）**——用处理器内部的小程序来解释执行。

## 为什么今天不能二选一

现代 x86 处理器能把外部的一条复杂指令拆成多个内部的小动作，叫**微操作（micro-operation，μop）**——外表是 CISC，内里跑得像 RISC。RISC-V 等指令集也可以有扩展，例如把某些常用操作编码成更短的指令，或让同一条指令批量处理多个值。所以比较时可以分别看软件写下多少字节，以及硬件拿到指令后要分几步做完，而不是给一个 ISA 贴上永久的快慢标签。

判断设计优劣应看工作负载和指标：

| 关注点 | 更规则指令的倾向 | 更复杂指令的倾向 |
| --- | --- | --- |
| 译码能耗 | 较低 | 较高或需缓存译码结果 |
| 代码密度 | 可能较低 | 往往较高 |
| 编译器责任 | 较大 | 部分转移给硬件 |
| 兼容负担 | 新 ISA 可较轻 | 成熟生态通常很重 |

## 与高级语言的联系

一个高级语句不对应固定的一条机器指令。优化级别、数据布局、调用约定和目标扩展都会改变生成代码；反过来，ISA 中容易表达的操作也会影响编译器的优化空间。软硬件接口不是墙，而是协同设计点。

程序会算、会绕圈了，但还缺一样日常结构：函数。跳过去容易，怎么回来、回来时寄存器里的值还算不算数？这需要[一套调用约定](calling_convention.md)。
