# 从汇编跳转到函数调用

## 函数自己又调用另一个函数，该把返回地址放哪？

设外层调用 `f()`，硬件把回到外层的位置留在**返回地址（return address）**寄存器 `ra` 里。`f()` 又执行一次调用时，同一个寄存器会被改成回到 `f()` 的位置——原来的返回地址就被冲掉了。怎么办？`f()` 可以在第二次调用之前把原返回地址存到内存里，等结果回来再恢复。运行中的函数常在一块按调用顺序先进后出的内存区域（**调用栈（call stack）**）中留出自己的一块，这块区域叫**栈帧（stack frame）**。这就是调用之间必须约定「谁保存哪个寄存器」的理由。

??? question "一个从不再调用其他函数的小函数一定需要栈帧吗？"

    若它只使用调用约定允许的寄存器、也无需保存局部数据，可能无需建立栈帧。具体取决于代码以及调用双方遵守的约定。

**先修**：[指令格式与寻址](instruction_format_addressing.md)、[最小汇编程序](assembly_risc_cisc.md)。

**读完能做**：说明参数、返回值、返回地址和临时状态分别放在哪里。

## 为什么只有跳转还不够

设调用方想算 `inc(41)`，算完还要继续执行。跳转指令本身只会改变 PC：它不知道参数在哪、结果放哪、回来落到哪。机器只看到寄存器和指令地址，所以调用方和被调用方必须事先约好三件事：参数在哪里、结果放在哪里、下一条回到哪里。对已编译代码生效的这类规则，是**应用二进制接口（Application Binary Interface，ABI）**的一部分。不同编译器遵守同一份规则，各自生成的代码就能互相调用。

以 RISC-V 的标准整数调用约定为例，参数从 `a0` 等寄存器传入，第一个整数结果放回 `a0`，常规调用使用 `ra` 保存返回地址。

```asm
    li   a0, 41
    call inc
    # 返回后 a0 为 42

inc:
    addi a0, a0, 1
    ret
```

`li`、`call` 和 `ret` 是汇编器提供的**伪指令（pseudo-instruction）**：写汇编时的简便写法，汇编器会把它们换成处理器能执行的指令序列。返回地址指向调用之后的指令。若 `inc` 自己还调用别的函数，下一次调用会覆盖 `ra`，于是需要先保存这次的返回地址——通常就保存在栈帧中。栈帧还可以保存局部变量和约定要求保留的寄存器状态。开头问题的答案就此完整：返回地址先在 `ra`，嵌套调用前转存进栈帧。

## ISA、ABI 与系统调用

| 层次 | 例子 | 它决定什么 |
| --- | --- | --- |
| ISA（指令集架构） | `addi` 或 `ecall` | 指令怎样改变机器状态 |
| ABI（应用二进制接口） | 用 `a0` 传第一个整数参数 | 编译后的调用者与被调用者怎样交换数据 |
| 操作系统的系统调用接口 | 通过约定传系统调用号和参数 | 怎样请求内核服务，以及如何返回结果 |

普通函数调用直接跳到同一个程序里的另一段代码。如果程序要请操作系统打开文件，就需要发起**系统调用（system call）**：处理器经约定入口把控制交给操作系统的核心部分（**内核（kernel）**），内核取得参数、执行权限检查，再返回用户程序。调用约定的同一思想，在这里升格为用户程序与内核之间的契约。继续读<a href="../../OperatingSystems/chapter_01_foundations/02_kernel_user_syscalls_interrupts.html">内核态、系统调用、中断与异常</a>。

## 自测

函数 A 调用 B，B 又调用 C。B 怎样记住 A 的返回位置？B 修改临时寄存器后，A 想继续使用原值，应该检查什么？

??? note "参考思路"
    B 在调用 C 前保存原有返回地址，之后恢复。对普通寄存器，要看 ABI 各自规定由调用者还是被调用者保存，不能假定所有寄存器都在调用后原样保留。
