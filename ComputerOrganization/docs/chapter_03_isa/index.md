# 指令系统结构 { #3 }

## 编译器和硅片说的是同一种语言吗？

走到这一步，你手里已经握住了计算机的两半拼图：往上，写过 C 或 Python 的人熟悉变量、循环和函数；往下，经过第 2 章和第 3 章，我们见识了 0 和 1 怎样编码数字，也看到了加法器、多路选择器和寄存器怎样在时钟节拍下运转。

可这两半世界之间依然隔着一道鸿沟：高级语言里既没有「3 号寄存器」，也没有「把多路选择器拨到左边」；反过来，加法器和触发器压根不认识 `for` 循环，也听不懂什么叫「调用函数」。究竟是什么把软件工程师的意图，严丝合缝地翻译成硅片上千百万个电子开关的动作？

答案就是我们在第 1 章立下的那座核心界碑——**指令集架构（ISA）**。编译器负责把高级程序翻译成符合 ISA 规范的机器指令序列，处理器则负责按 ISA 规定的语义把这些指令一条条执行出来。只要这份契约纹丝不动，底层的芯片实现就可以从最朴素的一拍一条指令，一路进化到极其复杂的超标量乱序处理器，而上层软件浑然不觉。第 4 章，我们就把这份软硬件之间的「正式合同」一页一页翻开看清。

## ISA 绝不只是一份「指令名字清单」

初学者很容易误以为，指令集架构就是列一张表，写明「本处理器支持加法、减法、乘法、跳转」。其实远远不止于此。设想一条最普通不过的内存读取指令：除了让两台兼容处理器认出「哪几个比特代表读取」，双方还必须提前白纸黑字约好——目标内存地址怎么算出来？多字节数据按什么顺序排在内存里？万一这个地址越界了、根本不让读，处理器该怎么向操作系统求救？

一份完整、能让操作系统和现代软件稳定运行的 ISA，至少需要规定以下五个方面的内容：

- **指令集合与二进制编码**：支持哪些操作，每条指令占多少比特，操作码、寄存器编号和常数各自排在哪几个位段；
- **架构可见状态**：处理器对外暴露多少个通用寄存器、每个寄存器多宽，以及程序计数器（PC）和其他特殊状态寄存器的行为；
- **数据类型与内存视图**：支持哪些整数与浮点宽度、多字节数据在内存里的排列顺序——即**字节序**（endianness）、地址对齐要求以及寻址空间的大小；
- **并发访存语义**：当多条指令甚至多颗核心同时读写内存时，软件能观察到哪些合法结果（这一部分会在第 10 章[多核与缓存一致性](../chapter_07_io_parallel/parallelism_consistency.md)里深入展开）；
- **异常与特权级机制**：当指令遭遇非法操作、除零或越界访存时，处理器如何精确暂停并转交给操作系统处理，以及哪些危险操作（如开关中断、改写页表）只允许操作系统内核执行。

少了指令编码，编译器无从下笔；少了异常、特权级和内存语义，操作系统与多线程程序就根本无从谈起。

## 本章导览：从单条指令到函数调用

为了让你循序渐进地把这份契约吃透，本章安排了三篇层层递进的正文：

1. **[指令格式与寻址方式](instruction_format_addressing.md)**：把一条 32 位机器指令放到显微镜下拆开，看看有限的 32 个比特怎样在操作码、寄存器编号和常数之间做零和博弈，又怎样靠五种寻址方式访问广阔的内存空间。
2. **[最小汇编程序与 RISC/CISC](assembly_risc_cisc.md)**：把单条指令串成真正能算 `c = a + b`、能跑 `for` 循环求数组和的最小汇编程序，亲手跟踪寄存器与内存的变化，再回望 RISC 与 CISC 两条指令集设计路线的博弈与融合。
3. **[从汇编跳转到函数调用](calling_convention.md)**：循环和判断有了，可真实软件离不开层层嵌套的函数调用。本节将揭晓为什么光靠硬件的跳转指令远远不够，还必须靠软件共同遵守的调用约定与调用栈，函数才能有去有回、互不踩踏。

## 一个直觉：ISA 像法律条文，微体系结构像执行机构

理解 ISA 与硬件实现之间的关系，一个颇为贴切的类比是「法律条文」与「执行机构」。

法律条文（ISA）白纸黑字规定了什么行为合法、会产生怎样的外部后果；至于执行机构（微体系结构）内部安排几名办事员、采取串行审批还是流水线并行审批，只要对外呈现的最终结果和例外处理严格符合条文，就都算合法实现。于是，两台同属 RISC-V 阵营的处理器，一台可以老老实实每拍启动一条指令，另一台可以一拍发射四条指令并乱序执行；只要每一条指令提交后的架构状态与异常行为丝毫不差，它们就完美共享同一个软件生态。

当然，别忘了类比的边界：现实中的法律条文偶尔还有模糊地带、要靠法官斟酌解释，而 ISA 面对的是毫无通融余地的编译器与晶体管——哪怕差了一个比特的定义，整个系统就会立刻失灵。

## 本章自测

读完本章三篇正文后，试着不翻笔记回答下面三个问题：

1. 为什么在定长 32 位指令里，操作码数量、通用寄存器个数和立即数取值范围三者之间必然存在此消彼长的取舍？
2. 只允许 `load` 和 `store` 指令访问内存、其余运算全在寄存器之间完成的 `load/store` 架构，为什么能大幅简化处理器电路？它又付出了什么代价？
3. 同一串 32 位二进制数 `0x005302B3`，放到不同 ISA 的处理器上为什么可能触发完全风马牛不相及的操作？
