# 指令系统结构 { #3 }

## 先看一段能念出来的汇编

用[数组地址算出要读哪一项](assembly_risc_cisc.md)，再[拆开这条指令](instruction_format_addressing.md)，找出哪几位告诉处理器「做什么」，哪几位告诉它「从哪里取数」。读到函数时，再追[调用怎么来、怎样回去](calling_convention.md)。

指令系统结构（ISA）是软件与处理器共同遵守的契约。编译器按照它生成机器码，处理器按照它改变架构状态；只要契约不变，内部实现可以从简单单周期核心升级到复杂乱序核心。

## ISA 需要规定什么

例如，一条读取指令既要让两台机器认出「读取」是哪几位，也要约好地址如何算，以及地址无法读取时如何报告。指令规则通常涵盖以下内容。

- 指令集合、机器码编码与操作数位置；
- 通用寄存器、程序计数器和其他软件可见状态；
- 数据类型、字节序、对齐和地址空间；
- 如何读写内存，以及多个执行者同时访问时能观察到哪些结果，[多核一章](../chapter_07_io_parallel/parallelism_consistency.md)会再展开。
- 指令无法正常完成时怎样报告异常，以及怎样把部分特殊操作留给操作系统。

ISA 不只是“指令名字清单”。如果没有异常与内存语义，操作系统和并发程序就无法可靠运行。

## 直觉：ISA 像法律，微体系结构像执行机构

法律规定什么行为可被观察，执行机构可采用不同流程完成。两台处理器可以执行同一 RISC-V 程序，一台每拍只启动一条指令，另一台可以每拍启动多条；只要最终架构状态和异常行为满足 ISA，它们都是正确实现。
