# 数据通路与指令周期

## 一条读取指令，怎样把地址 `140` 和内容 `42` 分毫不差地送到终点？

刚学完[最小汇编程序](../chapter_03_isa/assembly_risc_cisc.md)，先在脑海里把两块存储区域划清界限：**寄存器**是处理器核心内部数量极少、带编号的超高速存储格（`x0` 到 `x31`）；**内存**则是处理器外头按字节编址的广阔空间。看到 `x10 = 128`，意思是 10 号寄存器里存着整数 `128`；至于内存门牌号 `128` 对应的房间里住着什么数，必须真的拿着这个地址去敲内存的门才知道。

现在，把时间定格在一条指令即将执行的瞬间：

```asm
lw x5, 12(x10)
```

此时此刻，程序计数器 `PC = 256`，寄存器 `x10 = 128`，寄存器 `x5 = 9`，内存地址 `140` 开始的 4 个字节里存着整数 `42`。等这一拍时钟落下，寄存器 `x5` 里的 `9` 会神奇地变成 `42`，`PC` 会变成 `260`。

中间短短不到一纳秒里，硬件究竟干了些什么？算出来的地址 `140` 和从内存搬出来的值 `42` 都是 32 位整数，数据通路怎么保证把 `42` 而不是 `140` 送进 `x5`，又怎么顺手把 `PC` 推到了 `260`？让我们一块砖一块砖地搭起这条通路，再把这条 `lw` 从头到尾实况走一遍。

## 组装数据通路：一台最小 CPU 需要哪几件家当？

指令本身只是静躺在内存里的一串 0 和 1。**数据通路**（datapath）的使命，就是把取指令、读寄存器、算术运算、读写内存和写回结果接成一条环环相扣的硬件高速公路，让位串沿着导线真正流转起来。

搭一台能完整运行基础 RISC-V 指令的教学型数据通路，一共只需要七种核心硬件积木（全部都能用第 3 章的组合电路与时序电路造出来）：

1. **程序计数器（PC）与指令存储器**：PC 是一枚专门存放当前指令地址的寄存器；指令存储器接收 PC 送来的地址，吐出对应的 32 位机器指令。
2. **寄存器堆**：把 32 个通用寄存器集中打包在一块电路里，配备**两个读端口**和**一个写端口**——这样像 `add x7, x5, x6` 就能在同一拍里同时取出 `x5` 和 `x6`，写端口则在时钟边沿到来、且写使能有效时把新结果写入目的寄存器。
3. **立即数生成器**（immediate generator）：负责把指令位串里零碎排布的立即数（比如 I 型的 12 位偏移或 S/B 型拆分拼接的偏移）提取出来，并做符号扩展，还原成标准 32 位有符号数。
4. **算术逻辑单元（ALU）**：数据通路里的万能算术工位——既能替 `add` 算两数之和，也能替 `lw`/`sw` 算内存有效地址，还能替 `beq` 做减法比较两数是否相等。
5. **数据存储器**：承接内存读写请求。给它地址并拉高读信号，它送出该地址处的数据；给它地址、待写数据并拉高写使能，它在时钟沿将数据写入内存。
6. **多路选择器（MUX）**：遍布在各个数据汇合口上的「铁路道岔」，负责从多条候选数据线里放行当前指令真正需要的那一路。
7. **PC 更新加法器与分支判断电路**：一边用专门的加法器稳稳算出顺序下一条指令的地址 `PC + 4`，另一边用另一台加法器算出分支目标地址 `PC + offset`，再根据比较结果决定下一拍 PC 究竟听谁的。

## 五个逻辑阶段：所有指令共享的骨架

把一条指令从出生到落幕的全过程切开，无论最终建成单周期、多周期还是流水线机器，都可以整齐地划分为五个逻辑阶段：

1. **IF（取指，Instruction Fetch）**：把当前 PC 送入指令存储器取出 32 位指令，同时算出顺序下一条地址 `PC + 4`；
2. **ID（译码，Instruction Decode）**：解析指令里的操作码与寄存器编号，从寄存器堆读出源操作数，同时由立即数生成器还原符号扩展后的立即数；
3. **EX（执行，Execute）**：把操作数送进 ALU——算术指令算出计算结果，访存指令算出内存有效地址，分支指令完成大小或相等比较并算出跳转目标；
4. **MEM（访存，Memory Access）**：只有访存指令在这里真正动手——`load` 按地址读出数据，`store` 按地址写入数据，其他指令则安安静静绕道而过；
5. **WB（写回，Write Back）**：把最终结果（来自 ALU 或来自数据存储器）经由写回多路选择器送回寄存器堆，在时钟上升沿写入目的寄存器，同时把新的下一条地址锁存进 PC。

并非每一条指令都会把五个工位全都用满，但用这套统一骨架串起所有指令，既让单周期控制清清楚楚，更为第 6 章的五级流水线打下了现成的蓝图。光说不练太抽象——现在就把开头那条 `lw x5, 12(x10)` 放进这套骨架，一步不落地走完它！

## 实况走查：跟踪 `lw x5, 12(x10)`

重温一下初始现场：`PC = 256`，`x10 = 128`，`x5 = 9`，内存地址 `140` 处存放着 32 位整数 `42`（这里先聚焦 CPU 内部，暂略第 8 章才会引入的虚拟地址翻译）。

| 逻辑阶段 | 这一步拿到了什么输入 | 硬件部件干了什么 | 产出什么新信号 / 新状态 |
| --- | --- | --- | --- |
| **IF 取指** | `PC = 256` | 指令存储器按地址 `256` 读出指令；PC 加法器同时计算 `256 + 4` | 指令 `lw x5, 12(x10)`，候选下一 `PC = 260` |
| **ID 译码** | 32 位指令位串 | 认出操作码为 `lw`、源寄存器 `x10`、目的寄存器 `x5`；读寄存器堆并符号扩展立即数 `12` | 源操作数 `128`、扩展后立即数 `12` |
| **EX 执行** | `128` 和 `12` | 多路选择器把立即数 `12` 送入 ALU 第二端口，ALU 执行加法 `128 + 12` | **有效地址 `140`** |
| **MEM 访存** | 有效地址 `140` | 数据存储器读使能拉高，按门牌号 `140` 取出 4 字节数据 | **内存读出值 `42`** |
| **WB 写回** | ALU 的 `140` 与内存的 `42` | 写回多路选择器放行内存读出值 `42`；寄存器写使能拉高，时钟沿到来 | `x5` 从 `9` 变为 `42`，`PC` 从 `256` 变为 `260` |

请死死盯住 **EX** 和 **MEM** 这两行，把两个关键数字分得一清二楚：**`140` 是 ALU 算出来的门牌号，`42` 才是数据存储器按这个门牌号取出来的真正内容！**

到了最后写回（WB）路口，两根电线同时摆在寄存器堆的写入端前——一根传着 ALU 算出的 `140`，另一根传着数据存储器吐出的 `42`。是谁把 `42` 精准放进了 `x5`、把 `140` 挡在门外？正是第 3 章学过的**多路选择器（MUX）**！执行 `add` 指令时，控制器把这枚 MUX 拨向 ALU 那一侧；执行 `lw` 指令时，控制器把同一枚 MUX 拨向数据存储器那一侧。硬件连线一丝没动，数据流向却随指令应声而变。

请注意：表格把过程画成五步，是为了帮人眼理清严格的因果顺序。在**单周期教学机**里，这五步的组合电路首尾直连，电信号在一个漫长的时钟周期里一口气从左传到右，所有状态变更（更新 `x5` 和更新 `PC`）则在同一个时钟上升沿一并提交。等到了第 6 章的流水线，我们才会把这五段真正切开，让五条不同的指令同时站在五个工位上齐头并进。

??? question "保持同样的初始状态，如果把指令换成 `sw x5, 12(x10)`，数据通路里会发生哪些不一样的事？"

    前三个阶段几乎一模一样：取指拿到 `sw`，译码不仅读出基址寄存器 `x10 = 128` 和偏移 `12`，还顺便从寄存器堆的**第二个读端口**读出待写入数据 `x5 = 9`；ALU 依然稳稳算出有效地址 `140`。真正的分岔发生在 MEM 和 WB：数据存储器收到地址 `140`、写数据 `9` 以及拉高的写使能信号，把 `9` 写进了内存地址 `140`；而寄存器堆的写使能被坚决关闭，因此指令结束后 `x5` 依然保持原值 `9`，只是内存 `Mem[140]` 从 `42` 改写成了 `9`！

## 同一套数据通路，如何通吃四大类指令？

看懂了 `lw`，再把其余三类核心指令放进同一张图纸里逐一核对，你会惊叹这套硬件复用得多么精妙：

### 1. 寄存器算术指令：`add x7, x5, x6`

取指、译码后，寄存器堆同时吐出 `x5` 和 `x6`；ALU 第二输入的 MUX 选择「来自寄存器堆」，ALU 执行加法；随后结果直接绕过闲置的数据存储器，通过写回 MUX 选择「来自 ALU」，在时钟沿写进 `x7`，`PC` 稳步更新为 `PC + 4`。

### 2. 内存读取指令：`lw x5, 12(x10)`

寄存器堆读出 `x10`，立即数生成器把 `12` 符号扩展，ALU 第二输入的 MUX 拨向「来自立即数」，算出有效地址：

$$
\text{EA} = R[x10] + 12.
$$

随后数据存储器按 $\text{EA}$ 读出 4 字节，写回 MUX 拨向「来自数据存储器」送入 `x5`。因为 `lw` 把指令存储器、寄存器堆、ALU、数据存储器和写回通路从头到尾一个不落地全走了一遍，它往往就是单周期处理器里最耗时的那条指令。

### 3. 内存写入指令：`sw x7, 8(x10)`

`sw` 充分用上了寄存器堆的两个读端口：端口 1 读出基址 `x10` 送进 ALU 和偏移 `8` 相加得出有效地址；端口 2 读出要存进内存的值 `x7`，沿着旁路直接送到数据存储器的「写数据」入口。MEM 阶段拉高数据存储器写使能，同时**死死关掉寄存器堆写使能**，防止垃圾信号冲毁任何寄存器。

### 4. 条件分支指令：`beq x5, x6, label`

寄存器堆同时读出 `x5` 和 `x6` 送入 ALU 做减法比较（如果两数相等，ALU 的 `Zero` 标志线亮起 `1`）；与此同时，专用的分支加法器把当前 `PC` 加上符号扩展后的分支偏移算出跳转目标地址。如果「当前指令是分支」且「`Zero` 标志为 1」，PC 入口处的 MUX 就果断切到分支目标地址，否则乖乖走顺序的 `PC + 4`。对分支指令而言，它最终改写的架构状态既不是通用寄存器、也不是内存，而是 `PC` 自己。

## 为什么数据通路上到处都是多路选择器？

回顾刚才四类指令的走法，你会发现多路选择器（MUX）几乎每隔几步就会冒出来一个：

- **ALU 第二输入口**放一个 MUX：决定第二个操作数听寄存器堆的（如 `add`、`beq`），还是听立即数生成器的（如 `addi`、`lw`、`sw`）；
- **寄存器写回口**放一个 MUX：决定写进目的寄存器的是 ALU 算出的数（`add`）、内存读出的数（`lw`），还是 `PC + 4`（函数调用保存返回地址 `jal`）；
- **下一 PC 入口**放一个 MUX：决定下一拍顺着走 `PC + 4`、跳往分支目标，还是跳往寄存器间接地址（函数返回 `jalr`）。

如果为每条指令都单独修一条专属电路，芯片面积会膨胀成天文数字。**正是多路选择器，把昂贵的 ALU、寄存器堆和存储器变成了全班共享的公共资源**——不同指令只需在岔路口拨动一下道岔，就能在共享硬件上走出完全不同的数据流。

## 单周期 CPU 的速度魔咒：全班迁就最慢的那个人

单周期数据通路结构清爽、一拍一条指令，听起来简直完美无缺。可一旦拿秒表掐算它的运行速度，一个致命缺陷立刻原形毕露。

在单周期设计里，所有指令必须在一个时钟周期内全部走完。按照第 3 章学过的关键路径铁律，时钟周期 $T_{\text{clk}}$ 必须长到足以容纳最慢的那条指令——也就是走满全部五个阶段的 `lw`：

```text
PC -> 指令存储器 -> 寄存器堆 -> ALU -> 数据存储器 -> 写回寄存器堆
```

假设给各部件一个直观的估算耗时：指令存储器 $200\text{ ps}$、读寄存器堆 $100\text{ ps}$、ALU $200\text{ ps}$、数据存储器 $200\text{ ps}$、写回寄存器堆 $100\text{ ps}$。算下来，`lw` 全程需要整整 $800\text{ ps}$，于是整颗芯片的时钟周期被迫锁死在 $800\text{ ps}$（主频仅 $1.25\text{ GHz}$）。

可再看看 `add` 指令：它压根不碰数据存储器，全程只需要 $600\text{ ps}$；分支指令甚至更短，只需 $500\text{ ps}$！然而在单周期机器里，即便 `add` 提前 $200\text{ ps}$ 就干完了活，也只能站在原地发呆，干等时钟走满 $800\text{ ps}$ 才开启下一条指令——就像全班集体郊游，走得最慢的那个同学拖慢了整个队伍的步伐。

为了衡量平均每条指令耗费多少个时钟周期，我们引入一个后续将反复使用的核心指标——**每条指令平均时钟周期数**（Cycles Per Instruction，简称 **CPI**）。在单周期 CPU 中，每条指令恰好占 1 拍（$\text{CPI} = 1$）。若一段程序总共执行 $I$ 条指令，其总 CPU 执行时间为：

$$
T_{\text{CPU}} = I \times 1 \times T_{\text{clk}}.
$$

哪怕 $\text{CPI}$ 漂亮地等于 $1$，被最慢指令硬生生拉长的 $T_{\text{clk}}$ 依然把性能按在地上摩擦！

怎么破局？历史上先后出现了两条路：

- **多周期设计**：把漫长的 $800\text{ ps}$ 切成大约 $200\text{ ps}$ 一拍的短节拍，让不同指令按需走不同拍数（`beq` 走 3 拍、`add` 走 4 拍、`lw` 走 5 拍），顺便还可以在不同拍复用同一个 ALU 和存储器省下芯片面积，代价是控制器要增加状态机来记住当前走到第几步；
- **流水线设计**：同样把路径切成大约 $200\text{ ps}$ 一段，却不等上一条指令走完全程，而是每过一拍就紧接着放进一条新指令——既享受了短时钟周期，又力图把平均 CPI 维持在接近 1！

## 别忘了「意外改道」：数据通路里的异常

在结束数据通路的探险之前，还有一条不能遗漏的隐蔽支路——**异常**。

执行到一半时，意外随时可能发生：译码阶段发现一串根本不合法的操作码，或者访存阶段发现有效地址没有自然对齐、甚至指向了无权访问的内存页。此时，正常的 `IF → ID → EX → MEM → WB` 必须立刻紧急刹车并改道：

1. 立刻拉低受影响部件的写使能，**坚决阻止出错指令把坏结果写进寄存器或内存**；
2. 把出错指令的地址（当前 `PC`）和出错原因码存进专门的系统控制寄存器，方便操作系统事后排查；
3. 把 `PC` 入口处的 MUX 猛地拨向预先设好的异常处理程序入口地址，把接力棒交给操作系统内核。

所以，异常绝不是事后硬贴在处理器外头的「补丁」，从一开始它就是数据通路里「下一状态选择」的有机组成部分。

现在，整张数据通路的铁轨、道岔和加工站已经全部铺设完毕。但一列火车不会自己决定在哪个道岔左转还是右转——究竟是谁盯着那 32 位指令，在每一拍精准拉高或拉低每一根写使能、拨动每一个多路选择器？下一节，我们拆开 CPU 的大脑：[数据通路的控制器](control_unit.md)。
