# CPU 数据通路与控制 { #4-cpu }

## 先预测值，后画电路

在[一次读取](datapath_instruction_cycle.md)里写下地址 140 和内容 42，分别标明由谁产生。然后读[控制器](control_unit.md)，弄清 CPU 为什么只写回 42，以及同一套部件如何改成存储或加法。

ISA 只规定“结果应该是什么”，CPU 需要决定“数据实际经过哪些部件、每个部件何时动作”。**数据通路（datapath）**负责搬运和运算，**控制器（control unit）**负责选择路径、决定哪些部件可以写入。允许某部件写入的那根信号线叫**写使能（write enable）**。二者配合，把静态的机器码变成一步步的状态变化。

## 三类状态

1. **程序进度**由程序计数器（PC）保存，指出接下来去哪里读指令。
2. **计算状态**：寄存器堆保存近期操作数与结果。
3. **存储状态**：内存保存大规模数据和代码。

组合部件在状态之间计算，时钟边沿提交新状态——正是第 3 章时序电路的思想，只是规模放大到整颗处理器。只要沿着“读状态—组合计算—写状态”追踪，再复杂的 CPU 也可以拆解。

## 单周期、多周期与流水线

**单周期（single-cycle）**设计让每条指令一拍完成，直观，但时钟必须迁就最慢的那条指令；**多周期（multi-cycle）**设计复用硬件、把一条指令拆成多拍，降低面积并缩短时钟；流水线则让不同指令占据不同阶段，提高吞吐量。三者可以实现同一 ISA，区别在性能、控制复杂度和资源成本。哪种更好？这正是本章和下一章（流水线）要反复权衡的问题。
