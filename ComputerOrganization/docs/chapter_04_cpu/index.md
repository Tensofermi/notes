# CPU 数据通路与控制 { #4-cpu }

## 一串静静躺着的 0 和 1，怎样自己「动」起来？

到第 4 章为止，我们已经写出了像 `lw x5, 12(x10)` 这样清晰可读的汇编，也知道它在内存里不过是一串 32 位的二进制数字。可如果把这串 0 和 1 单独摆在桌上，它自己既不会去查 `x10`，也不会去算加法，更不会去敲内存的门。

那么，当我们按下电源键、时钟节拍开始嘀嗒作响，处理器内部究竟发生了什么，才让这一串静态的机器码真的变成了实打实的寄存器更新和内存读写？

答案藏在一对默契配合的硬件搭档里：

- **数据通路**（datapath）好比工厂里的传送带与加工机床——寄存器堆、加法器、算术逻辑单元（ALU）、多路选择器和存储器全连在上面，负责真正搬运和加工数据；
- **控制器**（control unit）则是整座车间的总调度员——它读懂当前指令的操作码，立刻向各个岔路口发出切换信号，并精准控制每一台存储部件的「写入总闸」，也就是决定这一拍允不允许修改状态的**写使能**（write enable）信号线。

第 5 章的核心使命，就是亲手把第 3 章的逻辑零件和第 4 章的指令契约装配在一起，造出一台真正能跑通 `add`、`lw`、`sw` 和条件分支的完整 CPU。

本章由两篇紧密咬合的正文组成：

2. **[数据通路的控制器](control_unit.md)**：同一套硬件部件既要跑 `add`、又要跑 `lw` 和 `sw`，控制器如何靠一排控制信号和写使能开关，让它们各行其是、绝不误写？同时比较硬布线控制与微程序控制的工程取舍，并理解异常为何本质上也是一次受控的控制流切换。

读完这两篇之前，不妨先在草稿纸上做个小预热：试着预测一条 `lw` 指令执行时，数据是从哪里读出、经过谁加工、最后怎么避开「地址」而把「内容」写进目的寄存器的，再带着你的预测走进正文核对。

## 拆解任意 CPU 的万能视角：三类状态 + 组合计算

哪怕面对市面上最新、最复杂的现代处理器，只要抓住我们在第 3 章学过的时序电路本质——**「读出旧状态 → 组合电路计算 → 时钟沿写入新状态」**——再庞大的芯片也瞬间有章可循。把视野放大到整颗 CPU，处理器维护的状态无非三大块：

1. **程序进度状态**：由**程序计数器**（PC）保存，指明当前该去内存哪个位置取下一条指令；
2. **近期计算状态**：由**寄存器堆**集中保存，为 ALU 提供高速操作数，并承接刚刚算出的结果；
3. **大规模存储状态**：由**内存**保存，装下整个程序的代码与海量数据。

每一拍时钟节拍之间，指令存储器、寄存器堆、ALU 和多路选择器就像一片巨大的组合逻辑海洋，根据当前状态算出下一拍的 PC、新寄存器值和内存写数据；时钟上升沿一响，所有被「写使能」放行的状态部件同步翻转，程序就稳稳向前推进了一步。

## 单周期、多周期与流水线：三条演进路线

同样为了实现同一份 RISC-V 指令集契约，数据通路和控制器可以有三种截然不同的节拍组织方式：

- **单周期**（single-cycle）设计最直白：每条指令无论简繁，一律在一个时钟周期内从取指跑到写回全部搞定。它好理解、控制逻辑简单，但致命伤在于「时钟周期必须迁就最慢的那条指令」，所有简单指令都得跟着磨洋工；
- **多周期**（multi-cycle）设计把一条指令拆成若干较短的步骤，简单指令少走几拍、复杂指令多走几拍，还能在不同拍里复用同一个 ALU 和存储器以节省面积，代价是控制器必须变成记住步数的有限状态机；
- **流水线**（pipeline）则更进一步，像现代汽车工厂一样让多条指令同时占据不同工位、重叠推进，成倍抬高指令吞吐量，但也随之引出了相互牵绊的冒险难题。

单周期为什么会慢、多周期怎么省面积、流水线又凭什么一举称霸现代处理器？这一章我们先拿单周期和多周期打通数据通路与控制的任督二脉，下一章（第 6 章）便顺势全速冲进流水线的世界。
