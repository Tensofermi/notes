# 存储层次 { #6 }

## 分清机器找的是地址还是数据

先用[16 字节缓存块](hierarchy_cache.md)观察连续读取为何容易复用数据，再用[虚拟地址 13000](virtual_memory_hardware.md)找同一页的翻译。有时要找的是一份数据，有时要找的是「程序用的这个地址，对应哪块实际内存」的记录。处理器会在两处分别保存近期结果。

理想存储器应当又快、又大、又便宜、掉电不丢失，但现实器件无法同时满足。**存储层次（memory hierarchy）**的思路是用少量快速存储保存“近期最有用的数据”，让多数访问接近上层速度，同时把容量和成本交给下层。本章就看这个思路的两大支柱：cache 与虚拟存储。

## 三类不要混淆的失败

一次 `lw` 没有立刻拿到数据，可能是三种完全不同的「失败」，处理者和时间尺度都不同。先补齐三个名词：内存按固定大小划分为**页（page）**，操作系统用**页表（page table）**记录某页对应哪块物理内存；专门记住近期翻译结果的小缓存叫 **TLB（Translation Lookaside Buffer，翻译后备缓冲区）**。若查页表后发现没有可用映射，或访问违反权限，处理器就会向操作系统报告**缺页异常（page fault）**。下表对应三处不同的检查。

| 现象 | 缺少什么 | 谁处理 |
| --- | --- | --- |
| 数据缓存未命中（cache miss） | 数据不在当前 cache 层 | cache 控制器与下层存储 |
| 翻译缓存未命中（TLB miss） | 地址翻译不在 TLB | 硬件或软件页表遍历 |
| 缺页异常（page fault） | 页表指示页面不在主存或权限不符 | 操作系统异常处理 |

三者可能在一次访存中连续发生，但时间尺度和责任边界不同。

## 存储墙

处理器运算速度的增长长期快于主存访问延迟的改善，两者之间的差距被称为**存储墙（memory wall）**。增加算术逻辑单元（ALU）的数量并不能让等待数据的程序更快——巧妇难为无米之炊。现代性能分析必须同时看计算、带宽、延迟和数据复用。
