# 虚拟存储的硬件支持

**第一次读**，先看下面的两次连续读取，再做地址 `13000` 的三条路径练习。对页号和页框还不熟，可以先用<a href="../../OperatingSystems/chapter_04_memory/01_address_space_paging.html">操作系统里的 16 字节小例子</a>算一次。多级页表、大页和缓存索引适合第二遍再读。

## 动机：让每个进程拥有自己的地址世界

程序希望地址连续、容量足够且不被其他进程破坏，物理内存却有限而零散。虚拟存储在虚拟地址与物理地址之间加入映射，同时提供：

- 进程隔离与页级权限；
- 灵活装载和共享；
- 按需把冷页面换到外存；
- 给程序近似连续的地址空间。

操作系统决定映射策略，硬件负责在每次访存的关键路径上快速翻译并检查权限。

## 连读两个整数，为什么可以复用翻译

设程序先读虚拟地址 `13000`，再读 `13004`。两次读取都在虚拟页 3 上，页内偏移分别为 712 和 716。页表记录「虚拟页 3 → 物理页框 20」。所以第一次查到这个映射之后，第二次完全可以沿用它。

假如硬件在**每一次**数据读取前都去读页表，即使两次读取只隔 4 个字节，也要重复走一遍翻译。于是处理器把刚用过的映射放在 **TLB**（地址翻译缓存，也叫快表）。它回答「这个进程的这页在哪个页框，可以怎样访问」。**数据 Cache** 则保存数据块的副本，回答「所需字节附近有没有更快拿到的一份」。把这两个问题先分开，后面就能判断一次读取卡在哪一步。

```text
虚拟地址 13004
    → 取出页号 3 与偏移 716
    → TLB 或页表给出页框 20，并检查权限
    → 拼出物理地址 82636
    → 数据 Cache 或主存给出这个位置的内容
```

如果相邻两次读取落在同一页，翻译可能复用；如果还落在同一块，数据也可能复用。两者的单位不同。以这里的 4096 字节页与 64 字节块为例，`13000` 和 `13064` 仍在同一虚拟页，映射到的 `82632` 和 `82696` 却落在不同的数据块。复用的前提是映射和权限仍然有效；操作系统修改它们时，要处理旧的缓存项。教学图按顺序画出依赖，具体硬件可以重叠部分操作。

## 页与页表

虚拟地址分为虚拟页号 VPN 和页内偏移：

```text
| virtual page number | page offset |
```

页表项（PTE）把 VPN 映射到物理页号 PPN，并保存有效位、读写执行权限、访问位和脏位等。页内偏移在翻译前后不变：

```text
| physical page number | same page offset |
```

若页大小为 4 KiB，页内偏移为 12 位。

原因是 4 KiB 等于 $2^{12}$ 字节，12 个二进制位刚好可以表示页内位置 0 到 4095。把地址除以 4096 时，余数就是这 12 位，其余高位形成页号。这样硬件可以直接拆位，不必为每条指令真的做一次通用除法。

## 为什么需要多级页表

若为巨大虚拟地址空间的每个页都预留 PTE，页表本身会很大。多级页表把 VPN 切成多段，只为实际使用的区域分配下级表，类似稀疏树。

代价是一次 TLB miss 可能需要多次内存访问才能走完页表。页表深度越大，地址空间扩展越容易，遍历代价也越高。

## TLB：翻译的 cache

TLB 缓存近期 VPN 到 PPN 的映射与权限。命中时可很快形成物理地址；miss 时由硬件页表遍历器或操作系统查页表，成功后回填 TLB。

若 TLB 命中时间为 $T_{TLB}$，命中率为 $h$，页表遍历平均代价为 $P$，忽略重叠时翻译开销近似：

$$
T_{translate}=T_{TLB}+(1-h)P.
$$

真实机器会让 TLB 查询与 cache 索引部分重叠，以缩短关键路径。

## TLB miss 不等于缺页

### TLB miss

翻译不在小型 TLB，但对应 PTE 可能就在内存中且有效。遍历页表、回填后即可重试，通常不需从磁盘读数据。

### page fault

PTE 表示页面不在主存、权限不允许或映射不存在，硬件触发异常。操作系统检查原因；按需调页时可能选择牺牲页、写回脏页、从 SSD 读入目标页、更新 PTE，再重启原指令。其代价可比普通指令高许多个数量级。

## 最小路径：一次 load

`lw x5, 8(x10)` 形成虚拟地址后：

1. VPN 查询 TLB；
2. 命中则得到 PPN 并检查读权限；
3. PPN 与原页内偏移组成物理地址；
4. 物理地址查询 L1 data cache；
5. cache 命中返回数据，最终写 `x5`。

若 TLB miss，先页表遍历；若 cache miss，再访问下级 cache 或 DRAM。两类 miss 独立存在。

## 同一个地址，推演三种结果

沿用<a href="../../OperatingSystems/chapter_04_memory/01_address_space_paging.html">操作系统的分页算例</a>。页大小为 4096 字节，虚拟地址 13000 位于虚拟页 3，页内偏移 712。若页表把它映射到页框 20，物理地址就是 $20\times4096+712=82632$。

| 当前状态 | 接下来发生什么 | 去哪找证据 |
| --- | --- | --- |
| TLB 没有页 3 的翻译，页表已映射且可读 | 查页表，缓存这个翻译，再继续访问数据 | TLB 未命中、页表遍历 |
| 这是合法地址，但页面尚未驻留 | 硬件进入异常处理，内核准备页面后重试；读文件、换入或零填充取决于映射 | 缺页与 I/O 统计 |
| 翻译已得到 82632，对应的数据块不在 L1 | 往下级缓存或内存取数据，适当时填入缓存 | 数据 Cache 未命中 |

这里用串行概念模型解释路径。部分处理器可以并行做 TLB 查询和 Cache 索引。一个缓存项存翻译，另一个缓存项存数据；页面是否存在、是否允许读取又是独立问题。

## 大页与覆盖范围

同样数量的 TLB 项，页越大，能覆盖的内存越多，适合大数据和数据库；也能减少页表层级。但大页增加内部碎片、分配困难和换页粒度，未必适合零散小对象。

TLB reach 为：

$$
Reach=N_{entries}\times PageSize.
$$

提升 reach 可以增加项数、增大页或混合页大小，各有面积、延迟和管理成本。

## cache 与翻译的先后

物理索引物理标记最直观，但必须等翻译后才能索引。虚拟索引可与 TLB 并行，却要处理不同虚拟地址映射同一物理页的同义问题，以及不同进程相同虚拟地址的重名问题。常见 L1 使用“虚拟索引、物理标记”，并让索引只依赖页内偏移范围。

## 权限、上下文与安全

PTE 的用户/内核、可写、可执行位是硬件隔离基础。切换进程后，旧 TLB 项不能被错误复用，系统可刷新 TLB 或用地址空间标识符区分。

推测执行还可能在权限检查结果确定前触碰 cache，形成侧信道。因此翻译与权限不只是性能机制，也是安全边界。
