# PCIe、网卡和 NVMe 的数据路径

## 一条链路上的两个设备，标称速度能直接相加吗？

假设每块盘单独顺序读都能跑 4 GB/s，两块一起读却经过同一条实际可传 6 GB/s 的共享路径。即使设备本身各能供给 4 GB/s，总体也被这条路径限制在 6 GB/s 左右。队列加深可以提供更多并发请求，但不会把共享链路变宽。

??? question "怎么在实验里区分盘慢和共享路径拥挤？"

    先测每块盘各自工作，再测两块同时工作，记录总吞吐、单盘吞吐和等待。若只有并发时下降，结合设备拓扑检查共享路径。

**先修**：[总线、设备控制器、DMA 和中断](io_interrupt_dma_storage.md)。

**读完能做**：从操作系统提交请求跟到设备完成，区分协议、链路和介质的瓶颈。

## 先跟一次读取

程序读取一段文件，内核发现数据没在页缓存里。文件系统把请求转给块设备层，驱动把读命令放入设备队列，再通过设备寄存器通知控制器。设备完成后，把数据通过 DMA 写入准备好的主存缓冲区，并通知驱动处理完成。具体路径随 I/O 模式和设备实现变化。

| 术语 | 在例子中的作用 |
| --- | --- |
| PCIe | 给 CPU 系统及设备提供数据传输链路，交换设备可以连接多条链路 |
| NVMe | 定义主机与存储控制器怎样提交命令、队列怎样工作、完成怎样报告 |
| SSD 介质 | 决定设备内部如何保存和读写数据，以及一些性能与可靠性特征 |
| 网卡 | 另一类设备，通常也有发送和接收队列，与主机内存交换网络数据 |

NVMe 命令排进队列，不意味着磁盘已完成读写。增加队列深度可能让设备保持忙碌，也可能让单个请求排得更久。两块设备各自的标称速率也不能直接相加，共享 PCIe 链路或交换设备时仍有总带宽上限。

## 算一个下界

若设备实际连续读取 4 GB/s，读 2 GB 至少约 0.5 s。若每次只读 4 KiB，等待一次 I/O 完成后才发下一次，单请求延迟又会主导吞吐。用同样的总字节数对比顺序大块和零散小块，不只看快了多少，还要看请求数、完成延迟与队列深度。

## 自测

两块 SSD 同时读时，各自速率下降，但 CPU 占用很低。列出两种可验证的解释。

??? note "参考思路"
    可能共享 PCIe 链路，也可能争用系统内存或其它设备路径。先查设备拓扑，再测单设备和双设备吞吐及队列等待。CPU 空闲只说明 CPU 未充分忙碌。
