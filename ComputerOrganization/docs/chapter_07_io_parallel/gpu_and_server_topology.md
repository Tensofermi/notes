# GPU、显存和服务器拓扑

**先修**：[DMA 与设备 I/O](io_interrupt_dma_storage.md)、[SIMD、多核与缓存一致性](parallelism_consistency.md)。

**读完能做**：说出数据在主存还是显存，判断慢的是计算、内存访问还是设备间传输。

## 从一个数组操作开始

要把一百万个值各乘以 2，每个元素可以独立处理。CPU 可以让向量指令操作多个元素，GPU 则适合让很多线程执行同一个计算核（kernel）。在 NVIDIA 的 SIMT 模型中，线程分组执行；同组线程走不同分支时，硬件可能分批执行不同路径，使部分线程暂时空闲。统一、连续的内存访问通常也比零散访问更有利于利用内存事务。

## 分清数据在哪一层

| 位置 | 存放例子 | 需要观察 |
| --- | --- | --- |
| CPU 主存 | 数据加载器生成的一批输入 | 主存带宽、CPU 与内存所属的 NUMA 节点 |
| GPU 显存 | 模型参数、中间激活与输入张量 | 显存容量、访问带宽和计算核的访问模式 |
| GPU 近端存储 | 寄存器、片上共享存储和缓存 | 每个线程组能否复用数据，是否需要重复读显存 |
| PCIe 或专用 GPU 互连 | 设备之间传输的张量 | 实际数据路径、是否能直接传输、链路或交换设备是否共享 |

服务器可有多个 CPU 插槽和 PCIe 根复合体。两张 GPU 各自可用，并不能告诉你它们之间的数据会经过哪条路径。还要看设备拓扑、设备及驱动支持的传输方式和链路负载。跨主机时，再把网卡、交换机和集合通信加入模型。

## 手算带宽下界

假设一批输入为 480 MB，主机到 GPU 的有效吞吐为 12 GB/s，单批传输至少约 40 ms。一个计算核若只需 10 ms，并且无法与传输重叠，计算与传输合计约 50 ms。若改用两个缓冲区，在理想流水线中准备下一批可以和当前批计算重叠，稳态仍受较慢的 40 ms 阶段约束。前提是硬件、运行时和数据依赖允许重叠。

选择 GPU 时，可以把 H100、H200、B300 之类的型号整理成同一张对照表，比较计算格式、显存容量与带宽、互连接口、功耗和实际部署拓扑。先用同一个工作负载说明需要比较哪几列，再查具体配置。

## 自测

显存占用率高、计算单元活动很低，能否直接判断 GPU 算力不足？

??? note "参考思路"
    显存占用说明分配了多少容量。低活动还可能来自数据加载、主机到设备传输、同步或网络等待。按时间观察这些阶段，再判断瓶颈在哪里。

运行模型和内存访问机制见 [CUDA Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/)。
