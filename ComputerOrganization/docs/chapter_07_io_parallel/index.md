# I/O、性能与并行 { #7-io }

## 跳出 CPU 孤岛：整台机器如何协同搬运与并行计算？

前八章里，我们几乎把全部注意力都锁死在了「单颗 CPU 核心 + 缓存 + 主存」这个小世界里。可一台真正摆在桌面上、或静静轰鸣在机房里的计算机，绝不可能关起门来只和自己的内存条自言自语。

你敲下键盘的瞬间、网卡从光纤里吞进视频流的瞬间、程序从固态硬盘加载几十 GB 模型权重的瞬间，都是外部世界在向处理器敲门。更现实的是，今天的服务器早就不再依赖单颗核心单打独斗，而是塞进了数十颗共享内存的 CPU 核心，以及通过高速总线挂在旁边的多块 GPU。

一旦走出单核孤岛，机器立刻面临两道全新的硬核拷问：

1. **快慢悬殊的协作难题**：CPU 算一条加法不到一纳秒，键盘按键却可能隔好几秒，固态硬盘读一页也要几十微秒。处理器总不能傻站着原地干等慢设备吧？它该隔三岔五自己去问，还是让设备办妥了主动来敲门，甚至干脆把搬运大块数据的体力活直接外包给设备？
2. **多方并发的秩序难题**：当多块硬盘共用一条高速通道、多颗 CPU 核心同时改写同一片内存、多块 GPU 需要来回同步庞大的张量时，大家怎么抢路、怎么保证彼此看到一致的数据、又怎么判断到底是谁拖了整台机器的后腿？

围绕这两道大题，紧接着的**第 9 章**与**第 10 章**将带我们把视野彻底拉宽到整块主板乃至整台多卡服务器。

## 一条贯穿始终的主线：让并行活动井然有序

把 I/O、多核和 GPU 放在一张大图上俯瞰，你会发现它们本质上都在解决同一件事——**如何协调多个同时运转的执行者，既让它们尽量并行干活，又绝不把共享通道和共享数据弄乱**：

- 在 **I/O 层面**，CPU 继续跑计算的同时，网卡和 NVMe 固态硬盘通过 DMA 悄悄往内存搬运数据；如果多块盘挤在同一条 PCIe 通道上，硬件仲裁与流量控制就得决定谁先通行；
- 在 **多核与 GPU 层面**，几十颗 CPU 核心或上万条 GPU 线程同时对庞大数据阵发起冲锋，硬件一致性协议、原子操作和高速卡间互连则负责把各自算出的结果分毫不差地汇合起来。

## 分清两把标尺：延迟与带宽

踏进设备与并行世界之前，最后再擦亮一对极易混淆的尺子——**延迟**与**带宽**（bandwidth）：

- **延迟**回答「第一滴水从水龙头流出到抵达终点，需要等多久？」（单次操作的端到端等待时间）；
- **带宽**回答「水流接通之后，一秒钟能灌满多少升水？」（单位时间能够稳定搬运的总数据量）。

把水管加粗一倍（提高带宽），灌满一整座泳池的时间确实会减半，但**第一滴水流过漫长管道所需的时间（延迟）并不会因此缩短**！所以，加载几个 GB 的大型数据集时，你最该盯紧持续传输带宽；而响应键盘按键、处理高频小包网络 RPC 或发起单次随机 4 KiB 读盘时，卡死体验的往往是那甩不掉的单次延迟。

带着这双眼睛，让我们先走进第 9 章第一篇，看看 CPU 和各类外设究竟怎样「对话」与「搬砖」。
