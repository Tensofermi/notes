# I/O、性能与并行 { #7-io }

## 用一张图标出每一份数据在哪里

跟一次[CPU 发起的设备读取](io_interrupt_dma_storage.md)，看数据实际走过的[设备与链路](device_data_paths.md)。理解了搬运后，再看[多个核心为何争同一缓存块](parallelism_consistency.md)，以及[把计算交给 GPU](gpu_and_server_topology.md)何时值得。

键盘什么时候有输入，由用户决定；磁盘什么时候读完，由设备进度决定。处理器如果一直原地等待，就空出了本能用来计算的时间——它该一直问，还是等设备来叫？本章从**输入与输出（input/output，I/O）**入手，先看设备怎样主动通知处理器、怎样自己搬数据，再讨论多个执行者一起工作时怎样协调。

## 一条共同主线

共同问题是**并行活动怎样协调**：设备可以在 CPU 计算时继续搬运，两个核心也可以同时求和再合并结果。如果双方都需要同一条通道，就得决定谁先用。可以先跟踪[一次存储读取经过的设备和链路](device_data_paths.md)，再看[多块 GPU 怎样经不同的机器连接方式交换数据](gpu_and_server_topology.md)。

## 延迟与带宽

延迟是完成一次操作要多久，**带宽（bandwidth）**是单位时间能完成多少数据。一条路每拍能搬更多字节，传一整批数据就更快，但第一个字节仍要花时间走完这条路——加宽水管不能缩短水流到的时间。读大文件时常关心持续传输速度，键盘输入则更关心按键后多久有反应。
