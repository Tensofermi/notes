# 总线、中断、DMA 与存储设备

## CPU 要不要盯着慢设备一直问？

假设程序等着接收网络数据。处理器可以不断问网卡「数据到了吗」，这种重复查询叫**轮询**。也可以在做其他事时，等网卡主动发来通知，这叫**中断**。如果要读入一大批数据，还可以先告诉设备该把字节放进内存的哪一段，让它自己搬完再通知。这种把搬运交给设备的方式叫**直接内存访问（DMA）**。

??? question "为什么高速设备有时仍选轮询？"

    当事件极密、等待极短时，每次进入中断的固定开销可能更高。轮询占用 CPU，但在合适负载下可降低响应和切换成本，也可与中断混合。

## I/O 的根本困难

设备种类多、速度跨度大、事件到达时间不可预测。CPU 不能为每种设备接一套专用指令和线路，也不应以纳秒级循环等待毫秒级设备。负责进出机器的数据传输称为**输入输出（I/O）**。例如，网卡可以在处理器做其他事时接收数据，完成后再通知，这种不必等在原处的方式叫**异步**。

## 设备控制器与内存映射 I/O

**设备控制器**是设备上负责执行命令并报告进度的硬件。它会留出少量可读写的位置，叫设备寄存器。例如，处理器可以读某个位置判断设备是否忙，再往另一个位置写入命令。让这些位置占据一些地址，就能用普通读写指令访问它们，这叫**内存映射 I/O**。

这简化了 ISA，却不能把设备寄存器当普通内存优化：某次读取可能清除状态，写入顺序可能有意义，cache 和乱序执行必须受限制。

## 总线与互连

传统总线共享地址、数据和控制线：

- 地址说明访问目标；
- 数据线承载内容；
- 控制线说明读写、大小、响应和错误；
- 仲裁器决定多个主设备谁先使用互连。

共享总线简单，但设备增多后带宽和电气负载受限。改用多条只连接两个端点的链路后，若传输经过不同通道，就有机会同时进行。共享某一通道时，仍要决定选哪条路、谁先通过，以及接收端来不及接收时怎样暂停发送。

## 轮询：最简单的同步

CPU 反复读取状态寄存器：

```text
while device_not_ready:
    read_status
transfer_one_item
```

轮询实现简单、响应时间可预测，适合事件极频繁或极短等待；若设备很慢，大量 CPU 周期被浪费。操作系统也会混合使用：低负载靠中断，高吞吐网络在一轮中断后批量轮询，减少频繁切换。

## 中断：设备主动通知

设备就绪后提出中断请求。处理器通常在可中断边界：

1. 保存必要的当前执行位置和状态；
2. 根据中断号找到处理程序；
3. 暂时屏蔽不适合打断当前处理的通知，例如低优先级事件；
4. 执行处理这类通知的代码，称为**中断处理程序**；
5. 恢复并继续原程序。

中断把等待时间还给 CPU，但有保存现场、流水线扰动和 cache 污染开销。中断合并可减少次数，却增加单个事件等待延迟。

中断与异常都改变控制流。区别在于异常通常由当前指令同步触发，中断来自外部并与当前指令异步。

## DMA：让设备直接搬大块数据

若每个字节都由 CPU load 后再 store，CPU 会成为搬运工。CPU 先准备记录，把从哪读、写到哪里、传多少字节告诉设备。负责搬运的控制电路能自行发起内存读写，支持在传完后用中断通知 CPU。内存中为这次输入预留的区域叫**缓冲区**。

DMA 的收益是降低指令开销并支持突发传输；代价包括：

- 与 CPU 竞争内存带宽；
- 需要固定、映射或描述缓冲区；
- 若设备直接写内存，而处理器还留着旧缓存，后续读取可能读到旧字节。某些平台能自动协调，也有平台要由软件按传输方向处理缓存，例如在设备要读取前先把改动写回内存。
- 设备能主动读写内存，因此需要限制它能访问的范围。有的平台用**输入输出内存管理单元（IOMMU）**翻译和检查设备提交的地址，只让它访问系统授权的缓冲区。

中断和 DMA 不是替代关系：DMA 搬数据，中断报告完成或错误。

## HDD：机械运动主导延迟

机械硬盘（HDD）用磁头读旋转的盘片。先移动磁头找到那一圈，这叫**寻道**；再等所需位置转到磁头下才能传输。各段耗时可以写为

$$
T_{disk}=T_{seek}+T_{rotation}+T_{transfer}+T_{controller}.
$$

随机访问频繁移动磁头，延迟高；连续大块读写摊薄机械开销，带宽更好。调度器会合并与排序请求，但过度排序可能损害公平性和请求时延。

## SSD：没有磁头，但并非“无限快内存”

固态硬盘（SSD）常用 **NAND 闪存**保存字节。它能一次读或写一个较小的页，却只能按包含多页的大块擦除。修改某页时，可以把新内容写到别处，再让**闪存转换层（FTL）**更新「系统看到的块号 → 实际芯片位置」的记录。等某个擦除块里积累了很多过时页，再搬走仍有效的内容、擦除整块，这叫**垃圾回收**。为了避免少数块过早用完擦写次数，设备还会尽量分散写入，这叫**磨损均衡**。

因此 SSD 仍有特性：

- 读通常快于写，擦除最慢；
- 零散的小写入可能引起额外搬运。设备实际写入比程序提交的更多，称为**写放大**。
- 系统可用 **TRIM** 通知设备哪些逻辑块已不用，回收时就可以跳过这些内容。
- 设备若有多个通道就能交叠处理请求，等待中和处理中一共有多少请求，可用**队列深度**描述。
- 偶尔碰上回收或搬迁时，请求比平时慢得多，体现在[尾延迟](performance_amdahl.md)上。

## 外设访问的完整例子

网卡接收到一小段按格式封装的网络数据（**帧**）时，可以用 DMA 把它写入预留的缓冲区。内核中负责操作网卡的代码叫**驱动**。驱动事先准备一串记录（**描述符**），逐条注明缓冲区的位置和大小。设备填好一个缓冲区后，更新对应记录，再发中断。驱动看到记录已经完成，才把数据交给内核中负责网络协议的代码，最后补充空闲的缓冲区。
