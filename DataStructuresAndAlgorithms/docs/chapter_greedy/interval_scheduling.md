# 贪心的适用条件：安排尽量多的区间

**先修**：[排序](../chapter_sorting/sorting_algorithm.md)、[贪心算法](greedy_algorithm.md)。

**读完能做**：用交换论证解释一个贪心策略，并用小反例判断什么时候该换算法。

假设一台机器一次只能运行一个任务。每项任务有固定起止时刻，半开区间允许一个任务结束的时刻立刻启动下一项。若目标是完成尽量多的任务，先选**结束最早**的可用任务，再做同样的选择。

任务 A 占用 `[0, 8)`，B 占用 `[1, 3)`，C 占用 `[3, 5)`，D 占用 `[5, 7)`。若按开始时间选，先取 A，只能做一项。按结束时间选择 B、C、D 能做三项。

为什么结束最早可以推广？取一份最优安排，把它第一个区间换成结束最早的区间。替换后，后续区间还都能放下，任务数也相同。剩余问题又是同一种选择。实现时先按结束时间排序，再扫一次，时间 $O(n\log n)$。

## 改一个条件

若 A 价值 100，其余每项价值 1，目标变成价值最大时，B、C、D 只有 3。此时可以用动态规划：把区间按结束时刻排好，比较「跳过当前项」和「选它并接上最后一个兼容区间之前的最优值」。

## 自测

你要最早完成一个任务，和你要完成尽量多任务，目标有何不同？如果任务可以让出机器后再继续，原模型哪条假设失效？

??? note "参考思路"
    第一个只需找结束最早的一项；第二个还需考虑后续可兼容项。允许中断和恢复时，任务不再必须连续占用固定区间，状态与调度策略都要重建。
