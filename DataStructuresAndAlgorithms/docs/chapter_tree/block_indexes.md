# 块存储与 B 树：让一次读取带回更多索引

**先修**：[二叉搜索树](binary_search_tree.md)。

**读完能做**：说明索引节点为什么常保存多个关键字，并辨认查找路径和换来的维护成本。

## 慢的是读一个块

在主存里，访问下一层节点往往只需要一次内存读取。若索引在磁盘上，而节点散落在不同的块里，每多一层就可能多一次块 I/O。一个块通常能存下多个键和指针，可以用一个块来指向许多子树，压低需要走的层数。

假设根节点有两个键 20 和 50。查找键 37 时，只需在根块内决定走 `(20, 50)` 那个子树，再去读对应块。块内可以线性扫或二分。这里比较的主要成本是读了几个块。

## 维护平衡要付出什么

B 树的节点能容纳多个键，叶子位于同一深度。插入而节点装满时，典型做法是分裂节点并把一个分隔键向上调整。根分裂时，树长高一层。删除也可能移动键、合并节点或使树变矮。

B+ 树变体常把数据记录或记录引用集中到叶子，用内部页做导航，并链接叶子以便范围扫描。节点加大可以降低层数，也会放大某些写入和更新的成本。选择时要看块大小、读写比例和范围查询是否常见。

## 自测

在缓存足够大、索引完全驻留内存时，B 树的块 I/O 优势会如何变化？

??? note "参考思路"
    磁盘 I/O 减少后，比较会转向 CPU 缓存局部性、块内查找时间、指针开销和更新成本。多键节点仍可能有性能优势，大小需要针对内存访问方式评估。
