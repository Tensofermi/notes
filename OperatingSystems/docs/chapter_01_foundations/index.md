# 操作系统基础 { #1 }

## 从开机跟到第一个程序

按下电源键的那一刻，内存里其实什么都没有：操作系统自己也是一个程序，它得先想办法把自己装进内存、接管机器，然后才能轮到你的程序运行。这引出了本章的第一个问题：[开机时内核怎样进入内存？](01_os_roles_architecture_boot.md)紧随其后的第二个问题是：程序跑起来以后，[怎样请求内核替它读文件？](02_kernel_user_syscalls_interrupts.md)

回答后一个问题需要几个贯穿全书的词。处理器用权限级别把运行环境分成两档：普通应用运行在权限受限的**用户态**（user mode），内核则在**内核态**（kernel mode）执行管理机器资源所需的特权指令。应用主动请求内核服务的受控入口叫**系统调用**（system call）；此外，设备发来的通知（**中断**，interrupt）和当前指令执行时遇到的问题（**异常**，exception），也会把 CPU 从用户态拉进内核态。

## 为什么先学边界与入口

进程、虚拟内存和文件系统看似是不同主题，但它们都依赖同一个边界：普通应用不能任意执行特权指令或访问内核数据，只能通过受控入口请求服务。时钟、缺页和设备完成也会让 CPU 暂停当前控制流，进入内核处理。

如果没有这层共同模型，后面几乎每一步都会走偏：系统调用容易被误解成普通函数调用，中断容易和异常混为一谈，调度也像是一个凭空发生的动作。先把边界画清楚，后面的进程、内存、文件才有地方落脚。

## 本章主线

```text
硬件上电
  -> 固件与引导程序
  -> 内核初始化
  -> 第一个用户空间进程
  -> 应用在用户态运行
  -> 系统调用 / 异常 / 中断进入内核
  -> 处理后返回或切换到其他执行流
```

## 与后续章节的连接

时钟中断为抢占式调度提供入口，缺页异常为按需分页提供入口，设备中断为异步 I/O 提供完成通知，系统调用则是文件、进程、网络和内存服务的统一入口。可以说，本章搭起的这套“事件到达、受控进入内核、处理后返回”的控制流框架，就是后面每一章反复使用的舞台。
