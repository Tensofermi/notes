# 虚拟内存 { #4 }

## 拿纸画两张页表

两个进程都说「读 26 号地址」，却能分别读到自己的字节——同一个地址，两处不同的数据。秘密在于：26 只是程序使用的**虚拟地址**（virtual address），处理器要先把它换算成内存条上的**物理地址**（physical address）才能取数。系统把虚拟地址按固定大小切成**页**（page），把物理内存切成同样大小的**页框**（page frame），再用一张**页表**（page table）记录每一页对应哪个页框。两个进程各有一张页表，同一个 26 自然被翻译到不同的页框。本章先用[16 字节小页](01_address_space_paging.md)手算一次翻译，再[比较三种查找结果](02_page_tables_tlb_faults.md)，最后回答[内存满了该换掉哪一页](03_replacement_allocation.md)。

## 地址翻译主线

每次访存都查页表太慢，处理器因此内置了一个保存近期翻译结果的小缓存，叫**TLB**（translation lookaside buffer，地址翻译后备缓冲）。找到翻译叫命中。没找到缓存记录时，先查页表。如果页表也没有可用映射，或权限不允许这次访问，才通过**缺页异常**（page fault）交给内核处理。

```text
CPU 产生虚拟地址
  -> TLB 命中：按权限检查，允许则用物理地址取数据
  -> TLB 未命中：查页表，有有效映射且权限允许则取数据
  -> 缺页异常：内核能补齐映射就重试，否则报告错误
```

## 与文件和 I/O 的连接

有些页的内容来自文件，可以把文件的内存副本（**页缓存**）直接映射给进程。另一些页用来保存堆、栈等运行中的数据，不对应某个文件，称为**匿名页**（anonymous page）。内存不够时，未修改的文件页可以直接丢掉，需要时再从原文件读取；已修改的文件页通常要先保存修改；匿名页则可以移到磁盘上专门暂存内存数据的区域——**交换空间**（swap space）。这些“页从磁盘来、回磁盘去”的路径，正是下一章文件系统与块设备故事的另一半。
