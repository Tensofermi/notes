# 虚拟内存与内存压力 { #4 }

## 同一个“26 号地址”，怎么会存着两份完全不同的数据？

打开电脑上的两个程序，它们各自向 CPU 发出一条一模一样的指令：“帮我读取 26 号地址里的字节。”令人称奇的是，程序 A 稳稳拿回了属于自己的字符，程序 B 也稳稳拿回了属于它的另一份数据——两边的编号完全相同，却丝毫没有撞车，谁也看不见谁的秘密。

拆穿这场“人人独占一整片内存”的魔术，只需抓住一个核心拐弯：程序嘴里喊出来的 `26`，根本不是内存条上焊死的真实编号，而是操作系统发给它的“虚拟门牌号”。每次读写内存前，处理器硬件都会悄悄翻开当前进程专属的一张对照表，把这份虚拟门牌换算成内存条上的真实物理位置。因为进程 A 和进程 B 手里各执一张互不相同的对照表，同一个 `26` 在两张表里自然指向了两处八竿子打不着的物理角落。

本章的三篇文章，就从最直观的手算开始，一步步把这套虚拟内存大厦建起来：先拿[16 字节迷你小页](01_address_space_paging.md)亲手算一遍地址翻译，顺便看清分页、共享与写时复制的巧思；接着直面 64 位机器的真实规模，在[页表、TLB 与缺页](02_page_tables_tlb_faults.md)里解开“表太大怎么存、查太慢怎么提速”的双重困局；最后迎战内存条被塞满的极限时刻，在[页面置换与内存分配](03_replacement_allocation.md)里回答“该请哪一页出门”以及“空出来的内存块怎么切分给千奇百怪的对象”。

## 一次访存背后的三级阶梯

哪怕把对照表建好了，真实硬件也不会傻乎乎地每次读写都去内存里翻一遍大表——那样程序跑起来直接慢一半。处理器在芯片内部配了一小块极快的翻译速查缓存，专门记着最近刚查过的几条换算结果。只有速查缓存里没找着，硬件才去翻完整的对照表；而如果连对照表里都写着“这页还没准备好”或“权限不够”，才会拉响警报请操作系统内核亲自下场救火：

```text
CPU 发出一个虚拟地址
  -> 第 1 关（极快）：命中翻译缓存且权限合法 -> 直接拼出物理地址取数据
  -> 第 2 关（稍慢）：翻译缓存未命中 -> 遍历内存里的页表，有效则回填缓存并取数据
  -> 第 3 关（进内核）：映射无效或越权 -> 触发缺页异常，由内核补齐映射后重试，或判为非法访问
```

把这三级阶梯印在脑子里，后面遇到“缓存未命中”“缺页”“读磁盘”这些最容易搅成一团的词时，你一眼就能分清此刻正停在哪一级台阶上。

## 通往文件系统与 I/O 的桥梁

读到本章末尾你会发现，虚拟内存并不是一座悬浮在内存条里的孤岛——它和硬盘有着千丝万缕的血缘。进程地址空间里，有一大片页面的内容原本就来自磁盘上的程序代码或数据文件（内核把它们留在内存副本里并直接映射给进程）；另一类存放堆、栈等运行时临时数据的页面没有对应文件，内存吃紧时如果需要腾地方，还得把它们暂存到磁盘上划出来的交换区域里。内存和磁盘之间这套“需要时请进来、压力大时送出去”的双向通道，正是下一章[第 6 章 文件、文件系统与设备 I/O](../chapter_05_storage_io/index.md)要接力讲完的另一半故事。
