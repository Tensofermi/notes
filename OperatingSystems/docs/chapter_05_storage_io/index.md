# 文件系统与 I/O { #5-io }

## 一次打开、两次读取、一次保存

先追[文件名如何找到内容](01_files_directories_inodes.md)。接着比较数据已在内存和要等设备时，[读取路径](../chapter_07_case_diagnostics/01_read_system_call_path.md)哪里不同。最后模拟[刚改完目录就断电](02_journaling_crash_disk.md)，看看怎样才算保存完成。

打开 `report.txt` 时，应用能按名字找内容，而存储设备只认识“第几号块”——按编号读写一块块字节。中间这道翻译由**文件系统**（file system）完成：它负责把文件名对应到内容，并组织更新后的数据怎样落盘。向设备读写数据统称**输入/输出**（input/output，I/O）。内核还会把已经读到的文件数据留在内存里供下次复用，这份副本就是[第一章](../chapter_01_foundations/index.md)预告过的**页缓存**。

## 两条相互交织的主线

```text
按名字找数据：路径 -> 目录项（名字和记录的对应关系） -> inode（文件记录） -> 文件数据块

向设备取数据：系统调用 -> 检查页缓存 -> 块层（给读写排队） -> 驱动（给设备发请求） -> 设备
```

文件系统关注“数据是什么、叫什么、崩溃后还是否一致”；设备子系统关注“请求怎样排队、怎样传输、完成后怎样通知”。一次真实文件 I/O 会同时经过两条主线，所以本章的四篇会反复在它们之间穿梭。

- 文件描述符为什么只是进程局部整数，而不是磁盘文件本身？
- 删除一个仍被进程打开的文件时，空间为什么不一定立刻释放？

## 关于性能的提醒

“磁盘慢”只是一个粗略判断。性能瓶颈可能位于路径解析、锁竞争、页缓存缺失、脏页回写、请求合并、设备队列、网络文件系统或应用访问模式。诊断时应沿层次逐步取得证据，而不是一看到 I/O 延迟就立即归因于硬件。
