# 保护、安全与虚拟化 { #6 }

## 当同一台机器里住进互不信任的“陌生房客”

前七章里，我们几乎总假设跑在电脑上的程序都是自己人——最多不小心写错指针或者死锁，还算不上居心叵测。可把视野放进今天的云服务器、多租户算力平台，甚至你每天用来打开陌生网页的个人电脑，前提立刻变了：**跑在同一块芯片上的程序，彼此可能完全不信任，甚至随时准备顺手牵羊或越狱搞破坏！**

怎么在同一套共享硬件上，给不同的用户、服务和团队画出一道道牢不可破的围墙？接下来的三章（第 8、9、10 章）将带你沿着“由浅入深、边界由软到硬”的阶梯一路往上走：

- 先在第 8 章[保护机制与系统安全](01_protection_security.md)里，盯紧一台单机上的一个图片缩略图程序，看操作系统如何按身份、权限、能力与系统调用过滤把它关进最小权限的笼子；
- 再在第 9 章[虚拟机与容器](02_virtual_machines_containers.md)里，把两个团队塞进同一台物理服务器——对比“给每人发一套虚拟硬件、跑各自独立内核（虚拟机）”和“共用宿主机内核、但隔离可见视图与配额（容器）”这两条截然不同的隔离路线；
- 最后在第 10 章[从镜像到进程](03_image_to_process.md)里，亲手把一个打包好的 Python 网页服务镜像跑成受限容器进程，把所有隔离边界一一验证落地。

## 一条贯穿始终的铁律：最小权限与威胁模型

设想一个只负责“读取一张图片、生成缩略图写回输出目录”的小工具。如果图省事直接拿管理员（`root`）身份运行它，一旦它用的图片解码库爆出内存越界漏洞，攻击者随手喂进一张精心构造的恶意图片，就能瞬间夺走整台服务器的最高控制权、翻遍所有人的密钥和数据库！

防止“一处失守、全盘沦陷”的基石，就是安全工程里最朴素也最锋利的**最小权限原则**（principle of least privilege）：**每个程序只应获得完成它本职工作所必需的那一点点权限，多一分都不给。** 落地之前，先停下来拿张纸写清三个问题——“我要保护哪些核心资产？最怕对方干什么坏事？攻击者能接触到哪一层接口？”把这些风险边界白纸黑字定下来，就构成了你的**威胁模型**（threat model）。没有威胁模型，安全设计就会沦为盲目堆砌配置。

从机制上看，操作系统与虚拟化提供的围墙主要落在两个互补维度：

| 边界类型 | 守卫的核心问题 | 典型内核与硬件机制 |
| --- | --- | --- |
| **访问与权限边界** | 这个身份到底能不能打开、修改或执行目标对象？ | [文件权限、ACL、Capability、MAC 与系统调用过滤](01_protection_security.md) |
| **资源视图与配额边界** | 这个程序能“看见”哪些进程和端口，最多能“吃掉”多少算力和内存？ | [虚拟机硬件隔离，或容器的命名空间（namespace）与控制组（cgroup）](02_virtual_machines_containers.md) |

切记：**围墙叠得越多，并不自动等于越安全。** 只要各层策略彼此打架、默认放行过宽，或者共用的底层内核出现高危漏洞，攻击者照样能找到一条缝隙一穿到底。

## 这一模块的三章路线（第 8–10 章）

- **第 8 章 · [保护机制与系统安全](01_protection_security.md)**：从谁能读写一张图片出发，厘清认证/授权/审计、ACL vs Capability、DAC vs MAC、沙箱过滤、TOCTOU 竞态与微架构侧信道。
- **第 9 章 · [虚拟机与容器](02_virtual_machines_containers.md)**：跟着同一个 `read()` 对比裸机、容器与虚拟机三条路径，拆透陷入与模拟（VM exit）、嵌套页表、设备直通与 IOMMU，以及 namespace + cgroup 组合拳。
- **第 10 章 · [从镜像到进程](03_image_to_process.md)**：把一个 HTTP 服务从静态镜像拉起来跑成受限容器进程，逐项检验端口映射、内存限额、权限裁剪与持久化挂载。

## 读完这三章，试着自己回答

- CPU 的用户态/内核态边界，和文件系统的读写权限位，各自挡住的是哪一类风险？
- [在文件旁边登记谁能访问（ACL），和直接给程序发一张专属凭证（Capability）](01_protection_security.md)，两种权限查验方向各自好在哪里、难在哪里？
- 为什么“用户登录认证成功”，绝不等于“他就被授权访问机器上的所有文件”？
- 虚拟机和容器分别共享了什么、又隔离了什么？为什么绝不能简单把容器称为“轻量级虚拟机”？

## 与前七章的血脉相连

学到这里你会恍然大悟：保护和虚拟化并不是凭空贴在操作系统外面的一层新漆，而是把前七章打造好的全部底座重新编排组合——第 5 章的页表权限隔开内存，第 2–3 章的调度器配合 cgroup 切分 CPU 配额，第 6 章的 VFS 权限与 fd 守住文件能力，第 1 章的系统调用入口负责收窄门禁，而 namespace 则把进程眼里看到的系统视图悄悄偷梁换柱。

读完接下来三篇时，建议一直揣着三句追问：**谁在门口实施检查？检查依据的身份和规则存在哪儿？检查放行后，程序拿到的是一次性操作许可，还是一张可以转手递给别人的持久凭证？** 带着这三问上路，再复杂的安全与容器配置都能一眼看穿。
