# 综合案例与诊断 { #7 }

## 每次只改变一个条件

在[系统调用案例](01_read_system_call_path.md)中对照第一次读和再次读。出现长时间等待时，先写下两个可能原因，再为每个原因选一项能区分它的[观测证据](02_diagnostics_self_test.md)。

例如，程序等了十秒才读到一段数据。它可能在等磁盘，也可能已经拿到数据，只差处理器把线程重新调回来。要区分这两种情况，可以分别记录设备请求完成和线程恢复运行的时间。

## 小结目录

- [一次 `read` 系统调用的完整旅程](01_read_system_call_path.md)：跟着读请求找到文件，比较数据已在内存和需要去设备取时的两条路径。
- [诊断工具、实验方法与自测](02_diagnostics_self_test.md)：按 CPU、调度、内存、文件、I/O 和系统调用层次组织观测工具，并提供综合自测题与参考思路。

## 为什么必须做综合路径

单独记住“`read` 是系统调用”远远不够。一次读取可能立即命中页缓存，也可能让线程睡眠；用户缓冲区可能触发缺页；设备可能通过 DMA 写入内存；返回前还要检查短读、信号和错误码。只有把条件分支画出来，才能解释性能和正确性现象。

## 诊断的基本循环

```text
描述现象
  -> 建立分层假设
  -> 选择低扰动证据
  -> 比较时间线与计数器
  -> 排除不符合证据的解释
  -> 做最小可复现实验
  -> 验证修复没有转移瓶颈
```

## 学完应能做到

- 解释缓存命中和缓存未命中时 `read` 路径的分叉。
- 区分进程正在运行、可运行但未获 CPU、睡眠等待事件三种状态。
- 为高 CPU、频繁切换、主要缺页、高 I/O 延迟分别选择第一批观测指标。
- 识别工具输出的限制，不把相关性直接当因果关系。
- 用前面章节的机制和权衡回答综合题，而不是只复述定义。
